== N6 修复（一行判据 + 文档） ==
tests/fixtures/execution/patches/order_outbox.patch, _component_status():
  -    if stored in _QUANTITY_TERMINAL:
  +    if stored in _QUANTITY_TERMINAL and not (stored == "FILLED" and filled < accepted):
原因：apply_event 的帧序是"先 _update(status=X) 再 apply_fill_revision(l)"，
处理 X="FILLED" 帧时落库 status 已是 FILLED 而本帧成交尚未入账（中间态）；
照搬"终态保留原状态"会走 working,terminal = 0,0 -> 守恒违规 -> QuantityError 被吞
-> 成交静默丢弃、行永久非法。判据只能是分量：FILLED 而 filled < accepted 不是终态事实。

修复前（n6_before.txt，tree_r3）：
  S1 部分成交->全成：status=FILLED filled=0.0105 working=0 terminal=0.0095
     viol=QuantityError: FILLED_STATUS_WITH_RESIDUAL; STATUS_FILL_MISMATCH
     risk[warn] "私有流成交未能落库 QuantityError THREE_COMPONENT_CONSERVATION_VIOLATION;
                STATUS_FILL_MISMATCH" action=fill revision skipped   last_error=None
  S3 一笔全成：status=FILLED filled=0 working=0 terminal=0.02  viol=同上（整笔丢失）

修复后（n6_after.txt，tree_r4）：
  S1 status=FILLED filled=0.02 working=0 terminal=0.00 viol=()  无 risk 事件
  S3 status=FILLED filled=0.02 working=0 terminal=0.00 viol=()
