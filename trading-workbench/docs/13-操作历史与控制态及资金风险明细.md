# 操作历史、控制态与资金风险明细

2026-11-11。代码、离线验收及运行态加载已完成；最新实机验收见文末。

## 使用入口

- 操作台 → 订单·成交 → **操作历史**；空订单面板先展开。
- 风险预算 → **资金与风险明细 →**，打开系统抽屉；也可从 `⋯ → 系统状态` 打开。
- 抽屉顶部提供 **暂停新开仓 / 切换仅平仓 / 恢复正常 / 紧急全平**。

暂停和仅平仓保留当前持仓与保护单。恢复正常仍由 Service 检查日亏损 / 回撤锁，不能绕过硬风控。每项操作先展示说明，再要求填写原因和大写确认词；暂停使用 `PAUSE`，恢复使用 `NORMAL`，仅平仓使用 `CLOSE_ONLY`，紧急全平使用 `EMERGENCY`。

紧急全平先把控制态落为 emergency，再尝试逐仓市价平仓。若无法证明全部成功，回执和历史标为“部分完成，需核对”，不会显示全部成功。提交期间不能关闭抽屉丢失请求上下文；按钮同步防重复点击。请求超时保留请求编号，显示结果未确认，不自动重试。

## 持久化操作历史

新表 `operation_history` 在本地 SQLite 账本内保存请求编号、动作、目标、原因、开始 / 完成时间、状态、错误码和精简回执。平仓、补挂、对账、控制态命令在 Service 执行前先写审计，执行后再收口。

状态包括 `pending / succeeded / partial / failed / unknown`。成交未确认（例如 `E_FILL_UNCONFIRMED`）属于 unknown，不当作确定失败。进程若在执行途中退出，pending 保留供核对，不自动补做操作。同一 request_id 二次提交返回 409，阻止重复执行。

UI 展示最近 100 条，支持按状态筛选、手动刷新、查看逐标的精简回执。旧版本的操作不补造；Host 参数 / 同源校验阶段拒绝、尚未送达 Service 的请求不会伪造执行历史。AI 链审计继续使用原 AI 审计体系。

## 盈亏口径

| 字段 | 口径 |
|---|---|
| 今日权益变化 | 当前可用的会话权益 − 北京时间当天首个可用权益快照；展示起算时间，可能不覆盖全天，不能当作已扣除出入金影响的交易利润 |
| 今日已实现盈亏 | 北京时间自然日内全部本地成交的 realized_pnl，用 Decimal 汇总；不受 UI 最近 100 条或列表 500 条上限影响 |
| 今日手续费 | 按币种分别汇总，不混加不同币种；显示历史币种 / 金额缺失条数 |
| 已实现扣手续费 | 仅当相关手续费完整且均为 USDT 时计算，明确不含资金费 |
| 完整净收益 / 资金费 | 数据源尚无完整资金费流水，保持“—”，不补零、不伪造 |

新增账本 `fills.commission_asset`，Broker 保存交易所返回的 commissionAsset。既有记录保持未知；若同一成交后续重新同步且取得真实币种，可以补齐币种元数据，不重复增加成交。

## 风险明细

展示保证金占用 / 上限、持仓数 / 上限、风控日亏损 / 阈值、峰值回撤 / 阈值、风控日基准及峰值权益、连续亏损 / 阈值、冷却截止、控制态原因和新开仓阻断项。

风险日沿用现有 Service 的 UTC 口径，UI 明确标注 UTC；操作时间、盈亏日及权益起算时间使用北京时间。资金风险明细来自当前 envelope 和账本，不把上轮 AI 风险建议冒充当前实际使用量。
