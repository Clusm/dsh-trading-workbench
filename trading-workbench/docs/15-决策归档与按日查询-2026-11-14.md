# 15 · 决策归档与按日查询（重新规划）

- 日期：2026-11-14
- 触发：工作台「AI 决策」目前只保留本地最近 100 轮摘要；用户要求**所有交易与决策链路信息都留档**，界面默认只看当天，其他日期按日期查询。
- 状态：**已实施（2026-11-15）**，见文末「实施记录」。改动面：`plugin/host/round-archive.js`（新增）、`plugin/host/integration.js`、`plugin/client.js`、三套测试。

## 1. 现状与问题

| 事实 | 位置 | 影响 |
| --- | --- | --- |
| 轮次存储上限 100 条 | `plugin/host/integration.js:116` `DEFAULT_STORE_MAX_ROUNDS = 100` | 第 101 轮写入时最旧一轮被静默丢弃 |
| 单文件整体重写 | `RoundStore.persist()` 每次 `JSON.stringify` 全量写 `data/host-rounds.json` | 轮次越多写入越慢，且上限 100 就是为了压这个成本 |
| 示范数据只有 100 轮 | `data/host-rounds.json` 恰为 100 条 | 更早的决策链（原因码、调用审计、证据哈希）已不可回溯 |
| 界面口径文案 | 轮次列表脚注「本地最近 100 轮摘要」 | 用户直接看到"只留100条" |
| 24h 预算独立 | `A05`：自动调度预算读 `data/auto-budget.json` 侧车 | **预算不受本轮改造影响**（已有测试 `A05: durable auto budget is not evicted by the 100-row UI round cache`） |

结论：100 条不是业务规则，是**单文件全量重写**的性能妥协。要留全量，必须换存储布局，而不是把 `maxRounds` 调大。

体量测算（按现有真实记录）：平均 21 KB/轮，其中 `result`（AI 调用与产出）占 88%。最坏 96 轮/日 → 约 2 MB/日、60 MB/月、730 MB/年；实际轮次远低于上限。

## 2. 目标

1. **不丢**：任何完成/失败/跳过/中止的轮次都落盘，含原因码、归因、逐调用审计、证据快照引用、闸门审计、执行结果。
2. **默认可读**：AI 决策页默认只显示**当天（Asia/Shanghai）**，与"今天在看今天"的直觉一致，首屏不被历史拖慢。
3. **按日查询**：选日期即可看到该日全部轮次摘要；点开仍走现有单轮详情（RoundView）。
4. **写入成本恒定**：新增一轮只追加一行，不重写历史。
5. **诚实边界不变**：不补造旧字段、不重算旧结论；读取到的就是当时写下的。

非目标：不引入数据库（SQLite/PG）；不改 Service 侧的 cycle 存储；不改评分与执行链路。

## 3. 存储设计（Host 侧）

### 3.1 目录布局

```
data/
  rounds/
    2026-11-14.jsonl      # 当天全部轮次，一行一条（追加写）
    2026-11-13.jsonl
    ...
    _index.json           # 可选：日期 → 条数 / 首末时间（可随时由目录重建）
  host-rounds.legacy.json # 迁移后的旧单文件（只读留档）
```

- **一天一个 JSONL 文件**：日期即分区键，追加复杂度 O(1)，崩溃最多丢最后半行（读取时跳过坏行并记 `gap`）。
- **日期口径固定 Asia/Shanghai**：与界面「时间（北京时间）」一致，避免 UTC 跨日导致"昨天的轮次出现在今天"。
- **保留策略**：默认**全部保留**；`WORKBENCH_ROUNDS_RETENTION_DAYS`（默认 0=不清理）可配置，供磁盘紧张时按日归档/删除。
- **`_index.json` 只是缓存**：启动或目录 mtime 变化时重建；缺失不影响读取。

### 3.2 迁移

首次加载时：

1. 若 `data/rounds/` 不存在且 `data/host-rounds.json` 存在 → 按 `startedAt` 的 Asia/Shanghai 日期拆分写入 `rounds/<date>.jsonl`（保持每行一条，`roundId` 唯一）。
2. 原子写 `rounds/_index.json`，写迁移标记 `rounds/_migrated.json`（记录来源、条数、时间）。
3. 旧文件重命名为 `host-rounds.legacy.json`（不再追加、不再被读取，仅留档）。
4. 若迁移中途失败：已写入的行保留；下次启动以 `roundId` 去重续写（幂等）。

### 3.3 RoundArchive 接口（替换 RoundStore）

```js
class RoundArchive {
  constructor({ dir, retentionDays = 0, logger })
  append(record)                     // 写当天分区 + 更新内存缓存 + 追加索引
  listDate(date)                     // 该日摘要（新→旧），深度读盘一次后缓存
  listDates()                        // [{date, count, firstAt, lastAt}]，新→旧
  find(roundId)                      // 详情：按 _index 的 id→date 映射定位分区
  listRecent(limit)                  // 跨日最近 N 条：给 lastRouteSnapshot / 修复 / 看板使用
}
```

> 现有调用点语义必须保留：`lastRouteSnapshot()`、`repairStaleRunning()`、`listRounds()`、`getRound()`、评审/归因扫描等改为 `listRecent(1)` / `listRecent(N)` / `find(id)`，不能一律换成"今天"，否则跨日修复与"上一轮路由快照"会失真。

## 4. 接口（Host HTTP）

| 路由 | 语义 | 备注 |
| --- | --- | --- |
| `GET /api/rounds?date=YYYY-MM-DD` | 该日全部轮次摘要 | 参数校验：格式、不得晚于今天；缺省=今天 |
| `GET /api/rounds/dates` | 可查询日期列表 `{ok, today, dates:["YYYY-MM-DD", …]}` | 新→旧；条目数不做全量统计（只按目录列举，避免每次轮询读全归档） |
| `GET /api/rounds/:id` | 单轮详情（不变） | 由 `find(id)` 跨日定位 |
| `GET /api/state` | `rounds` = **今天**的摘要；新增 `rounds_date`、`available_dates`（轻量：日期字符串数组） | 其余字段保持不变；首屏只传当天 |

约束：
- 单次查询只允许一天（多日请分次），单日上限 2000 条并返回 `truncated` 标记，避免异常数据拖垮首屏。
- 日期参数非法 → 400 `E_DATE_INVALID`；未来日期 → 400 `E_DATE_FUTURE`（不允许"明天还没发生"）。
- 摘要字段与现在完全一致（`roundSummaryOf`），客户端渲染逻辑不用改。

## 5. 界面（AI 决策 → 历史）

1. **日期条**：`今天`（默认，高亮）· 最近 7 天（最多 7 个 chip，带条数）· `选择日期`（原生 `<input type="date">`，max=今天）· 刷新。
2. **历史表**：沿用现有列（时间/轮次/触发/结论/原因码/耗时/查看），只把数据源换成所选日期；筛选（全部/失败/不交易/成交、时长分档）在所选日期内生效。
3. **口径文案**：把「本地最近 100 轮摘要」改为「本地按日归档，保留全部轮次」；选中历史日期时附「历史日期：只读」。
4. **轮次侧栏**（AI 决策左栏）：随所选日期切换；今天仍按现有轮询刷新，历史日期只加载一次（不发轮询）。
5. **空态**：该日无轮次 → 「这一天没有轮次记录」+ 回到今天的按钮。
6. **i18n**：`ai.historyDate*`、`ai.archiveScope`、`ai.emptyDay` 等键中英文同时落表（`TEXT`），与现有 中文/EN 开关一致。
7. 若该日 `truncated=true`，表尾标注「该日记录超过上限，仅显示前 N 条」。

| 风险 | 对策 |

### 9.2 实际接口（与 §4 的差异）

- `GET /api/rounds?date=YYYY-MM-DD` → `{ok, date, today, rounds:[摘要], total, truncated}`；缺省=今天，未来日期 `400 E_DATE_FUTURE`，非法日期 `400 E_DATE_INVALID`。

- `GET /api/state` 增 `rounds_date`、`available_dates`；`rounds` 只含今天；`last_round` 仍是全归档最新一轮（跨零点不空）。

### 9.4 生效与回滚

- 生效：重载工作台 Host 插件（或重启 DSH）后，首次启动会把 `data/host-rounds.json` 迁移为 `data/rounds/<date>.jsonl` 并把旧文件改名为 `data/host-rounds.legacy.json`；客户端刷新页面即可看到日期条。
- 回滚：把 `data/rounds/` 移走、`host-rounds.legacy.json` 改回 `host-rounds.json`，并回退代码即可——归档文件是纯 JSONL，不依赖任何新索引。

### 9.5 重载后的首帧（2026-11-15 现场排障）

现象：重载插件后"第一时间没连上 Host 数据"，过一会才正常。实测与结论：

| 检查 | 结果 |
| --- | --- |
| `GET /api/state` | 200，5ms；`rounds_date=2026-11-15`、`rounds=[]`、`available_dates=[11-14…11-11]`、`last_round=11-14 21:59` |
| `GET /api/rounds?date=2026-11-14` | 200，8ms，33 条 |
| `GET /api/rounds/dates` | 200，4 个日期 |
| 归档迁移 | 00:42 完成：4 个分区 + `_migrated.json`，旧文件改名 `host-rounds.legacy.json` |
| Python 交易服务 8791 | **未运行**（无进程、端口未监听），日志最后一行 00:41:45 |

所以"没连上"不是归档坏了，而是三件事叠加：

1. **今天确实是 0 轮**：现在是 11-15 凌晨，100 轮全在 11-11～11-14 四个分区里；历史页默认"今天"必然空——点日期条选 11-14 即有 33 条（这正是本次改造的预期行为）。
2. **交易服务停了**：面板的"服务不可达 / 状态未知 / 账户与持仓为空"来自 Service 离线，不是 Host。
3. **重载窗口**：插件重载时路由会短暂注销/重注册，首次 `/state` 可能 404/503；旧轮询要等满 8s 才重试，表现为"Host 离线"停留很久。

已修第 3 点：失败后按 0.8s → 1.6s → 3.2s → 6.4s → 8s 退避重试（成功即恢复常规节奏），渲染套件新增 T27a–c 锁定。第 1、2 点属运行环境：选日期即可看到历史；交易服务需另行启动。

## 10. 一键启动本机交易服务（2026-11-15）

问题：服务没起来时，面板只能显示「服务不可达」，用户要去命令行跑 `scripts/start-service.ps1`。

### 10.1 设计

| 层 | 做法 |
| --- | --- |
| Host 路由 | `POST /api/service/start`（loopback + same-origin + JSON body 必需，动作写操作审计 `service/start`） |
| 启动方式 | 按插件自身位置推导启动器路径，`spawn` 虚拟环境 python + `service/run_service.py --host/--port/--data-dir`，`detached` + 日志写 `data/logs/service.{out,err}.log` |
| 成功判定 | **必须**等到 `GET {serviceBaseUrl}/health` 返回 `ok:true` 才算成功；45s 未就绪 → `504 E_SERVICE_START_TIMEOUT`（带 pid、等待时长、日志路径） |
| 幂等 | 已在跑 → `{ok:true, already:true}`，不重复拉起；同一时刻只允许一个启动（`409 E_SERVICE_START_IN_FLIGHT`） |
| 能力开关 | `/state.service_start = {supported, reason, command}`；`WORKBENCH_ALLOW_SERVICE_START=off` 关闭；缺 python/入口时 `supported:false` + `reason`（`PYTHON_MISSING` / `SERVICE_ENTRY_MISSING` / `DISABLED_BY_ENV`），UI 不渲染死按钮 |
| 诊断 | `/api/host.service_start` 带绝对路径、端口、超时、最近一次尝试；`/state` 只带轻量三元组（8s 轮询不放大） |
| UI | 服务不可达时，横幅动作从「系统状态」变成「启动服务」；点击后按钮进入「启动中…」，成功提示「交易服务已就绪（Ns）」，失败按错误码提示（`E_SERVICE_LAUNCHER_MISSING` → 找不到启动器） |

### 10.2 实测发现：Node 的 NO_PROXY 会打坏 Python 服务

现场用按钮同一条代码路径启动，服务 2.9s 就绪，但日志出现：

```
WARNING workbench.app supervisor_start_failed error=InvalidURL
```

根因：DSH/Electron 进程带 `NO_PROXY=localhost,127.0.0.1,::1,[::1]`；httpx 0.28 把 `[::1]` 解析成 `host:port`，抛 `InvalidURL: Invalid port: ':1]'` —— 服务的执行客户端构建失败，只能降级成只读。

- 复现：`httpx.Client()` 在该环境直接抛异常（已用 venv python 验证）。
- 修复：Host 派生子进程时规范化 `NO_PROXY/no_proxy`（去掉 IPv6 方括号），**保留**用户的代理（Demo 行情可能要走代理）；不把 Node 的环境怪癖传进 Python。
- 验证：修复后 `supervisor_start_failed` 增量为 0，`/health.supervisor=running`，`/api/ready` 200。

### 10.3 边界（诚实说明）

- 服务是 Host 的子进程：正常使用期间稳定；**关闭 DSH 应用**时它可能随进程树一起退出。需要长期后台运行请用 `scripts/start-service.ps1`。
- 一键启动只拉起进程，不改变控制态：`/api/ready` 仍会报 `CONTROL_NOT_NORMAL`（服务端控制态还是 pause）。要恢复交易，仍需顶栏「启动自动交易」（置 normal + 开调度）或手动「运行一轮」前先确认控制态。
- 重载插件后才能拿到新按钮（Host 侧新增路由），刷新页面才能拿到新 UI。
