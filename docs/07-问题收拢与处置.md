说明链路本身可用。**真正缺的是：可重复的测试 LLM、Demo 凭据、审计落库、UI 接线。**

### 3.2 复用原项目 Demo key（零明文复制）

上游 `.env` 中已有 `BINANCE_DEMO_API_KEY` / `BINANCE_DEMO_API_SECRET`，与
`credentials.py` 的键名完全兼容。只需在**启动服务的 shell** 里指定路径，不创建任何凭据副本：

```powershell
cd C:\Users\Tao\Desktop\币安\trading-workbench\service
$env:WORKBENCH_DOTENV_FILE = "C:\Users\Tao\Desktop\币安\multi-agent-trader\.env"
python run_service.py --port 8791
```

只读验证结果：`demo_credentials_configured=True`、`source=env_file`、
`service/.env.local` 仍不存在。优先级：进程 env → 指定 dotenv → `service/.env.local`。
只挑 DEMO 两个键，上游文件里的其它键（含实盘键）一律不读、不注入环境、不落日志。

> **安全边界**：启用后 `credentials_configured=true`，P2 才具备签名交易能力（Binance Demo
> 是虚拟资金，但走主网行情）。P2 仍需人工显式触发，不会自动下单；fixture 模式仍强制禁止。
> 本次工作**没有**重启服务，**没有**启用该能力。

### 3.3 用会话内 LLM 代替外部模型做测试

```powershell
# 在启动 DSH Host 的 shell 里
$env:WORKBENCH_LLM_MODE = "session_fixture"
$env:WORKBENCH_LLM_SCRIPT = "no_trade"    # 或 full_chain
```

生效后 `GET /trading-workbench/api/state` 的 `llm.transport` 为
`session-llm-fixture/1`、`llm.mode=session_fixture`。默认 `no_trade` 脚本只跑一次
`analysis` 并以 `NO_CANDIDATE` 收口，不依赖行情价格，适合验证 cycle/证据/审计/finalize；
`full_chain` 用固定离线证据价格跑满 8 次角色调用，适合离线测试，**不要拿它跑实时行情**。
fixture 模式无条件短路 P2，返回 `E_TEST_MODE_NO_ORDER`，绝不提交订单。
