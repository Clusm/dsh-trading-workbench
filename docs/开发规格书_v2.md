## 1. 项目目标与非目标

### 目标
1. 构建一个可运行的多 Agent 交易系统，主 Agent 能：
   - 汇总各情报 Agent 信息；
   - 从结构化策略卡片中匹配参考策略；
   - 自主决定开仓、平仓、加减仓或不做；
   - 生成带理由的 `TradeIntent`。
2. 每个 Agent 都有独立运行日志、输入输出留痕、成本统计和表现评分。
3. 每日自动生成交易总结与复盘报告。
4. 通过实战开发理解 Agent 编排、工具调用、状态管理、审计、风控、执行、复盘闭环；不额外编写教程。

### 非目标（V1 不做）
- 不接实盘资金。
- 不做秒级/高频做市。
- 不保证盈利。
- 不让 LLM 输出直接调用任意 Python 代码；只允许调用已注册的白名单工具。
- 不绕过币安 API 权限模型。

## 2. 总体架构

采用 **LangGraph** 做多 Agent 编排：每个 Agent 是图中的一个节点；情报 Agent 可并行，风控与执行是必经的确定性节点。

```text
每 5 分钟决策周期
        │
        ▼
┌─────────────────────────────────────────────────────────┐
│                    Scheduler / 状态入口                   │
└─────────────────────────────────────────────────────────┘
        │
        ├──▶ Market Agent（加密市场情报）
        ├──▶ Macro Agent（美联储/美股/宏观）
        └──▶ Onchain Agent（Web3 链上情报）   ← 并行，结果带 TTL 缓存
        │
        ▼
Strategy Agent（读取结构化策略卡片，按当前市场状态匹配参考卡）
        │
        ▼
主交易 Agent / Orchestrator（生成 no_trade / TradeIntent）
        │
        ▼
Schema 校验（Pydantic，格式错误直接拒绝）
        │
        ▼
Risk Agent（确定性规则 + 可选 LLM 解释）
        │
        ├── 拒绝 → 记录原因，本轮结束
        ├── 降额 → 修改数量/杠杆后放行
        └── 放行
             │
             ▼
Execution Agent（币安测试网适配器）
             │
             ▼
Order Tracker（成交回报、仓位对账、重启恢复）
             │
             ▼
Audit / Event Log（全链路落库）
        │
        ▼
Review Agent（每日复盘，UTC 00:30 运行）
```

LLM 可以参与决策和解释，但不能跳过 Schema 校验、Risk Agent、Execution Agent 三层。

## 3. Agent 清单与职责

| Agent | 类型 | 主要输入 | 主要工具 | 输出 | 运行频率 |
|---|---|---|---|---|---|
| `orchestrator` 主交易 Agent | LLM 决策 | 各情报简报、仓位、最近交易、策略卡片、风险额度 | `read_portfolio`, `query_strategy_library`, `propose_trade` | `TradeDecision` | 每 5 分钟或事件触发 |
| `market_agent` | LLM + 数据 | 币安公开行情 | K线、24h成交额、资金费率、OI、爆仓、盘口 | `MarketBrief` | 每 5 分钟 |
| `macro_agent` | LLM + 数据 | 美联储、美股、宏观 | Tavily 搜索、FRED、美股指数/VIX/美元/美债收益率 | `MacroBrief` | 每 1 小时 + 事件前检查 |
| `onchain_agent` | LLM + 数据 | Web3 链上 | DefiLlama、Etherscan 免费层、CoinGecko | `OnchainBrief` | 每 30 分钟 |
| `strategy_agent` | 确定性匹配 | 当前市场状态 | 读取 JSON 策略卡片，按规则打分匹配 | `StrategyRefs` 策略参考卡片 | 每次决策前 |
| `risk_agent` | 确定性规则为主 | `TradeIntent`、风险档位、账户状态 | 规则检查器 | `RiskVerdict` | 每笔交易必经 |
| `execution_agent` | 确定性执行 | 已批准的 `TradeIntent` | 币安测试网 REST | `OrderReceipt` | 实时 |
| `review_agent` | LLM 复盘 | 当日全部日志与交易 | 读取审计库 | 每日复盘报告、Agent 评分 | UTC 00:30 |

### 3.1 Market Agent
- 标的池：前 40 个 USDT 永续（按 24h USDT 成交额排序，可配置排除项）。
- 数据：5m/15m/1h/4h/1d K线，资金费率，未平仓合约 OI，24h 成交量，盘口深度，爆仓数据。
- 输出 `MarketBrief`：
  - 各周期市场状态（趋势/震荡/高波动/低波动）；
  - 强势/弱势标的 Top N；
  - 资金费率极端值；
  - OI 异动；
  - 需要主 Agent 注意的异常。
- 数据获取全部使用币安公开接口，不需要 API key。

### 3.2 Macro Agent
- 免费数据源：
  - FRED（美联储经济数据，免费 API）；
  - Tavily 搜索新闻与美联储日历；
  - 美股指数、VIX、美元指数、美债收益率（公开行情源）。
- 输出 `MacroBrief`：
  - 未来 24/72 小时宏观事件（FOMC、CPI、非农等）；
  - 风险事件等级；
  - 美股与加密市场相关性观察；
  - 对主 Agent 的建议（只能作为参考，不直接交易）。

### 3.3 Onchain Agent
- 免费数据源：
  - DefiLlama：TVL、稳定币市值；
  - Etherscan 免费层：大额转账、gas；
  - CoinGecko：趋势币种；
  - 以后有 key 再扩展 CryptoQuant/Glassnode。
- 输出 `OnchainBrief`：
  - 稳定币供应变化；
  - TVL 变化；
  - 大额转账/交易所相关地址活动；
  - 链上活跃度异常。

### 3.4 Strategy Agent
- 知识库：`策略报告_整理版.md`，后续可加入新策略文档。
- 输出 `StrategyRefs`：
  - 与当前市场状态相关的 1–3 张策略卡；
  - 适用条件是否满足的粗判；
  - 该策略在本轮决策中的“参考权重”。
- 明确规则：策略库**只读**，Agent 可以引用、变体、忽略，但策略本身不会自动生成订单。

### 3.5 主交易 Agent / Orchestrator
- 输入：所有情报简报 + 当前仓位 + 风险额度 + 最近 20 笔交易 + 策略参考卡片。
- 输出 `TradeDecision`，必须是以下之一：
  - `no_trade`：不交易及原因；
  - `open`：开仓意图；
  - `close`：平仓意图；
  - `reduce`：减仓意图；
  - `adjust`：修改杠杆/止损/止盈意图。
- 每个 `TradeIntent` 字段：
  - `symbol`, `side`, `qty`, `leverage`, `order_type`
  - `stop_loss`, `take_profit`
  - `expected_holding_minutes`
  - `confidence`（0–1）
  - `reasoning`
  - `strategy_refs`（引用了哪些策略）
  - `market_snapshot_ref`（引用了哪份简报）
- 主 Agent 不能直接下单，只能产出结构化意图。

### 3.6 Risk Agent
- 核心检查是纯 Python 规则，不经过 LLM：
  - 交易对是否在允许列表；
  - 杠杆/名义金额/保证金占用是否超过学习冒险档；
  - 日亏损是否触发熔断；
  - 回撤是否触发只平仓；
  - 是否重复单/冲突单；
  - 行情数据是否过期；
  - API/网络状态是否健康。
- 输出 `RiskVerdict`：`approved` / `reduced` / `rejected`，并给出可审计原因。
- 允许使用 LLM 生成“解释文本”，但解释文本不影响规则结果。

### 3.7 Execution Agent
- 只接币安 U 本位永续测试网。
- 支持：市价单、限价单、减仓单、平仓单、测试网止损/止盈。
- 所有减仓平仓必须 `reduceOnly`。
- 下单带 `clientOrderId` 幂等键，防止重复发送。
- 订单发出后由 Order Tracker 跟踪至终态；重启先对账再恢复。

### 3.8 Review Agent
- 每日 UTC 00:30 运行。
- 输出：
  - `reviews/YYYY-MM-DD.md` 复盘报告；
  - 每笔交易归因：判断错误 / 执行问题 / 数据问题 / 风控拦截正确 / 市场随机；
  - 每个 Agent 的贡献评分与错误清单；
  - 主 Agent 引用策略库后的实际表现；
  - 明日注意事项。

## 4. 审计与数据记录设计

### 4.1 数据库：SQLite
文件：`data/agent_trader.sqlite`

| 表 | 作用 |
|---|---|
| `agents` | Agent 名称、版本、模型配置 |
| `agent_runs` | 每次 Agent 运行：起止时间、状态、模型、token、估算成本、延迟 |
| `artifacts` | 每个 Agent 输出的结构化 JSON 文件路径与 sha256 |
| `llm_calls` | prompt/response 摘要、模型、token、成本、错误 |
| `tool_calls` | 工具名、参数、返回摘要、耗时、是否成功 |
| `trade_decisions` | 主 Agent 每轮决策：no_trade/open/close/reduce/adjust |
| `trade_intents` | 每个交易意图：全字段、状态流转 |
| `risk_verdicts` | 风控放行/拒绝/降额及原因 |
| `orders` | clientOrderId、交易所单号、成交、状态、时间戳 |
| `positions` | 当前与历史仓位快照 |
| `portfolio_snapshots` | 权益、保证金、未实现盈亏 |
| `risk_events` | 熔断、断线、异常、人工干预 |
| `daily_reviews` | 每日复盘与 Agent 评分 |
| `agent_scorecard` | 每个 Agent 的滚动评分 |

### 4.2 JSONL 原始日志
- `data/logs/YYYY-MM-DD/{agent}.jsonl`：每个 Agent 的完整输入、输出、错误。
- `data/logs/YYYY-MM-DD/llm_raw.jsonl`：完整 prompt/completion。
- 日志每天滚动，方便按日复盘。

### 4.3 每笔交易的必答问题
1. 当时哪些 Agent 提供了什么信息？
2. 主 Agent 引用了哪张策略卡？为什么？
3. 风控是放行、降额还是拒绝？
4. 订单从发出到成交用了多久？实际价差多少？
5. 最终盈亏应归因到哪里？

## 5. 交易决策周期

1. **T+0s**：Scheduler 触发一轮决策。
2. **T+0–20s**：Market/Macro/Onchain Agent 并行产出简报（有缓存则复用）。
3. **T+20s**：Strategy Agent 读取结构化策略卡片并匹配。
4. **T+20–60s**：主 Agent 生成 `TradeDecision`。
5. **T+60s**：Schema 校验 + Risk Agent。
6. **T+60–90s**：Execution Agent 发单。
7. **T+90s–终态**：Order Tracker 跟踪、对账。
8. **每轮结束**：全链路落库。
9. **每日 UTC 00:30**：Review Agent 复盘。

异常路径：
- LLM 超时/报错 → 本轮 `no_trade`，记错误；
- 数据源过期 → Risk Agent 拒绝开仓；
- 断网/API 连续错误 → 自动进入“只允许平仓”；
- 程序重启 → 先同步持仓和挂单，再恢复新开仓。

## 6. 风险档位

### 6.1 学习冒险档（测试网，已确认）
```yaml
profile: learning_adventurous
market: binance_futures_testnet
max_leverage: 20
max_margin_usage: 0.80        # 最多使用 80% 保证金
max_position_notional: 100000 # 单笔名义价值硬上限
max_open_positions: 3
daily_loss_stop: 0.15         # 日亏 15% 熔断
max_drawdown_from_peak: 0.30  # 回撤 30% 只平仓
allow_bare_position: true     # 测试网允许无止损裸仓
stale_data_block_seconds: 60
```

### 6.2 未来实盘档（仅作参考，接实盘前重新确认）
```yaml
profile: real_learning
market: binance_futures
max_leverage: 5
max_margin_usage: 0.20
max_position_notional: 10000
max_open_positions: 3
daily_loss_stop: 0.05
max_drawdown_from_peak: 0.15
allow_bare_position: false
```

### 6.3 永不关闭的技术保护
- 所有减仓/平仓订单强制 `reduceOnly`。
- 同一决策周期内不得重复发相同方向订单（幂等）。
- API Key 永不开启提现权限。
- 行情过期、账户状态无法核对时，不新开仓。
- 人工可在任何时刻切到 `pause` / `close_only` / `emergency_close`。

## 7. LLM 层设计

- 使用 OpenAI 兼容接口，当前默认走 SenseNova（https://token.sensenova.cn/v1）。
- 配置：
  - `DEEPSEEK_API_KEY`（key 后续给）
  - `DEEPSEEK_BASE_URL`
  - 默认模型：`deepseek-v4-flash`；主 Agent 使用 `deepseek-v4-pro` 且 `reasoning_effort=max`
- Mock 模式：没有 key 时返回固定/可配置的假响应，用于开发和测试。
- 每个 Agent 可单独配置 temperature、max_tokens、prompt 版本。
- 所有 LLM 调用记录 token 用量、延迟、成本估算、完整 prompt/response。
- 任何 Agent 输出都必须经过 Pydantic 结构校验，格式错误即拒绝。

## 10. 开发阶段、交付物与验收标准

| 阶段 | 内容 | 交付物 | 验收标准 |
|---|---|---|---|
| 0 | 工程骨架 + LangGraph + Mock LLM + 审计底座 | 可运行空图，事件全落库 | 不依赖任何 key 能跑通一轮 mock 决策 |
| 1 | 三个情报 Agent 接入免费数据源 | Market/Macro/Onchain Brief | 连续运行 24h，每个 Agent 有结构化输出与日志 |
| 2 | 策略库 Agent（轻量匹配） | JSON 策略卡片 + 状态匹配 | 给定 10 种市场状态，匹配到合适策略卡 |
| 3 | 主 Agent + 风控 Agent | TradeDecision 流水线 | 100 次模拟决策：格式合法、风控正确拒绝/放行、全留痕 |
| 4 | 测试网执行 | 下单、撤单、平仓、对账 | 完成 20+ 笔测试网订单，重启后持仓可对账 |
| 5 | 复盘 Agent | 每日报告、Agent 评分 | 连续 7 天自动生成复盘，交易可归因 |
| 6 | 自主假设 | Agent 提出并验证新交易假设 | 能在沙盒中生成假设并完成一次回测/模拟验证 |

预计开发量：9–12 个有效开发日；测试网观察期另加 1–2 周。

## 13. 前端方案（已确认：本地 FastAPI 控制台）

- 技术栈：FastAPI + Jinja2 模板 + 原生 JS，样式使用本地 CSS，不依赖前端框架/CDN。
- 启动：`scripts/run_web.py`，默认 `http://127.0.0.1:8000`，只监听本机。
- 运行方式：同一进程内启动后台决策循环；Web 端只读写 SQLite/控制状态，不直接拼订单。
- 页面：总览/控制、Agents、交易/订单、复盘。
- 控制接口：`POST /api/control` 支持 `normal` / `pause` / `close_only` / `emergency`。
- 手动触发一轮：`POST /api/cycle/run`。
- 以后若想练 React，后端 JSON API 保持不变，前端可整体替换。

## 14. Binance MCP Server 评估结论（2026-08-29）

- 目前**没有使用** Binance Agent-Native MCP Server。
- 评估文档：https://developers.binance.com/en/docs/agent-native/mcp-server/agentic
- 关键结论：
  1. MCP 每笔订单/转账都要求**用户确认**（confirm-before-execute），与本项目“主 Agent 自主决策”的目标冲突。
  2. MCP 面向 Binance.com 主账户体系下的 **Agentic 子账户**，未看到测试网支持；我们当前必须先跑币安测试网。
  3. MCP 需要交互式 OAuth 授权，不适合当前本地无人值守的 LangGraph 循环。
  4. 我们的执行层已用 REST + HMAC 完成，签名、下单、止损止盈、对账均可控可审计。
- 保留项：将来若增加“人工确认模式”或让外部 AI 客户端（Claude/ChatGPT 等）访问 Binance 主账户，可把 MCP 作为独立通道接入；测试网主链路仍用 REST。

## 16. 固定 500U 会话资金与自动重启规则

- 系统逻辑起始资金固定为 500U，与 Binance Demo 账户绝对虚拟余额解耦。
- 会话权益 = 当前交易所权益 - baseline；paper 模式 baseline=0。
- 会话权益 <= 1U 时：按资金保护流程全平 → 重置 baseline → 会话权益回到 500U。
- Demo 账户绝对余额只作为容器，不要求等于 500U；风控与主 Agent 看到的是 500U 起点后的会话权益。

## 17. 行情覆盖与交易目标
