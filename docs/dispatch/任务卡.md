用法：派发任务时以 JSON 条目为准确来源，本文件提供派发视图（线/波次/启动条件/审查/风险）。两者冲突时以 JSON 为准并回报 I 修正。

启动与验收统一规则：implementation_requires冻结后可基于夹具先行；depends_on是合入门槛。task_base_commit选已审核集成HEAD，记录pending_dependencies，不能所有后续任务都退回contract标签。I组成含共享适配的完整候选后，指定审核与Q针对精确commit验收；作者可本地提交，禁止推送/合并/打标签。JSON只由I更新，审查报告按任务/候选/角色/会话/轮次归档。

状态图例：均为 PLANNED（未分派）。波次：W0–W4 见手册 §3；后置任务在 W4 之后。
