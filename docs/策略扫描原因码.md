# 策略扫描原因码（U08 · C 决策证据 · DL07 / DC10 / F09）

状态：U08 交付（`src/core/strategy_funnel.py`）。**原因码分类轴冻结在 U05**：
本文档只做两件事——(1) 说明扫描/执行漏斗**每一道闸门**、(2) 登记**细分码 → 九码**
的映射表。**不新增原因码**，任何新细分码都必须在上表登记，否则
`detail_reason()` 直接 `UnknownDetailCode`（fail-closed）。

上游口径：`docs/contracts/README.md` §7（K05 轨迹与计数器）、§12 C#13
（funnel 状态枚举 / `no_trade` 一轮解释）；`docs/决策链路专项评估与优化报告_2026-09-19.md`
DL03（分离管理与研究）、DL07（漏斗/时延/原因可观测）与 DC10。

## 1. 为什么需要它（F09 / DL07）

旧口径里一轮扫描只留一个 `status`：

```
last_scan = {"status": "ok"|"error"|"deferred", "tickets": 0, "error_count": 0, ...}
```

`tickets=0` 与 `status=ok` 同时出现时**无法区分**下面这些完全不同的事实：

| 事实 | 旧口径 | 新口径（漏斗） |
|---|---|---|
| 收盘 bar 上确实没有信号 | `ok, tickets=0` | `stopped_at.signal_triggered`, detail `NO_SIGNAL_ON_CLOSED_BAR` / `NO_EDGE` |
| 行情取不到（DNS/限流/预算让步） | 可能仍是 `ok` | `MARKET_TRANSPORT_OUTAGE` / `MARKET_BUDGET_DEFERRED` / `KLINE_FETCH_FAILED` → `DATA_UNAVAILABLE` |
| 策略卡没注册 signal_fn | 只有 `risk_events` 一行告警 | `SIGNAL_FN_MISSING` → `VALIDATION_REJECTED` |
| 标的不在业务开仓白名单 | 被静默过滤 | `SYMBOL_NOT_IN_SCOPE` → `READINESS_BLOCKED` |
| 同一根 bar 已经发过信号 | 被 `seen` 静默去重 | `BAR_ALREADY_SEEN` → `NO_EDGE` |
| 有票据但价格不在入场区 | 只在 `reasoning` 自由文本里 | `PRICE_OUTSIDE_ENTRY_ZONE` → `NO_EDGE` |
| 研究预算被管理占用 | 不可见 | `MANAGEMENT_PRIORITY_BUDGET` → `MODEL_DEADLINE` |

因此 U08 的硬要求是：**任意一轮 `no_trade`、任意一张有效 ticket 都必须能回答
"为什么没开"**，而 `status` 只作为机器健康信号保留（不删、不改语义）。

## 2. 漏斗闸门（K05 README §12 C#13）

枚举在 `core.strategy_funnel.Stage`，顺序 = 评估顺序。每个候选
（`(策略卡, symbol, timeframe)` 三元组，或一张票据）**停在第一道过不去的闸门**。

| # | 闸门 | 类型 | 谁写入 | 含义 |
|---|---|---|---|---|
| 1 | `card_loaded` | 通过型 | 扫描器 | 候选入口（只参与"漏斗收窄"前缀计数） |
| 2 | `card_indicatorized` | 拒绝型 | 扫描器 | 策略卡未指标化（`indicatorized=false`） |
| 3 | `signal_fn_registered` | 拒绝型 | 扫描器 | `signal_fn` 未在内置运行时注册 |
| 4 | `symbol_in_scope` | 拒绝型 | 扫描器 | 非 USDT / 不在业务开仓白名单 |
| 5 | `timeframe_supported` | 拒绝型 | 扫描器 | 周期不在 `30m/1h/2h/4h/8h/1d` |
| 6 | `market_data_ready` | 拒绝型 | 扫描器 | K 线拉取失败/质量不合格/行数不足 |
| 7 | `signal_triggered` | 拒绝型 | 扫描器 | 策略函数输出非法、或收盘 bar 无信号、或扫描异常 |
| 8 | `side_allowed` | 拒绝型 | 扫描器 | 方向与该卡 `direction` 不符 |
| 9 | `features_complete` | 拒绝型 | 扫描器 | `adx/rsi/ema/macd/atr` 末值有 NaN |
| 10 | `bar_unseen` | 拒绝型 | 扫描器 | 同一根 bar 已发过信号（去重） |
| 11 | `ticket_emitted` | **通过型** | 扫描器 | 扫描侧全通、票据已落库 |
| 12 | `ticket_active` | **通过型** | 扫描器 | 跨轮/重启恢复出一张仍有效的票据 |
| 13 | `ticket_fresh` | 拒绝型 | 执行器 | 票据形状非法/过期/已消费 |
| 14 | `no_position_conflict` | 拒绝型 | 执行器 | 同 symbol 或同策略已有仓位 |
| 15 | `price_available` | 拒绝型 | 执行器 | 无最新价 / 建意图失败 |
| 16 | `in_entry_zone` | 拒绝型 | 执行器 | 当前价不在入场区 |
| 17 | `intent_ready` | **通过型** | 执行器 | 终态：真的产出了开仓意图 |

- **通过型闸门**（`card_loaded` / `ticket_emitted` / `ticket_active` / `intent_ready`）
  允许不带细分码，计入 `reached`；**拒绝型闸门必须带细分码**，否则 `FunnelItem`
  直接 `ValueError`（原因不允许缺失）。
- `stopped_at` 只统计拒绝型闸门（"为什么没开"的直方图）；`reached` 统计通过型
  （`tickets_emitted` / `tickets_recovered` / `opened`）。
- 轮级条目（`NO_TICKETS_AVAILABLE`）以 `origin="round"` 登记，**不计入候选数**，
  避免把"本轮没有票据"虚增成一个候选。

## 3. 细分码 → 九码登记表

`detail_reason(code)` 是唯一入口；`validate_detail_table()` 自检
"每个细分码都映射到九码"且"九码都有细分码可达"。

| 细分码 | 九码 | 语义 |
|---|---|---|
| `CARD_NOT_INDICATORIZED` | `NO_EDGE` | 该卡不是信号来源，本轮不参与 |
| `SIGNAL_FN_MISSING` | `VALIDATION_REJECTED` | 卡与运行时注册表漂移 |
| `SIGNAL_FN_OUTPUT_INVALID` | `VALIDATION_REJECTED` | 策略函数返回形态非法 |
| `SYMBOL_NOT_USDT` | `READINESS_BLOCKED` | 非 USDT 标的，不在业务范围 |
| `SYMBOL_NOT_IN_SCOPE` | `READINESS_BLOCKED` | 不在业务开仓白名单 |
| `TIMEFRAME_UNSUPPORTED` | `VALIDATION_REJECTED` | 周期不在支持集合 |
| `MARKET_TRANSPORT_OUTAGE` | `DATA_UNAVAILABLE` | DNS/TLS/限流等整轮传输故障 |
| `MARKET_BUDGET_DEFERRED` | `DATA_UNAVAILABLE` | 受控冷却/预算让步（预期降级） |
| `KLINE_FETCH_FAILED` | `DATA_UNAVAILABLE` | 单标的行情拉取失败 |
| `KLINE_QUALITY_REJECTED` | `DATA_UNAVAILABLE` | K 线质量/最终性不合格 |
| `KLINE_ROWS_INSUFFICIENT` | `DATA_UNAVAILABLE` | 可用收盘 bar 行数不足 |
| `NO_SIGNAL_ON_CLOSED_BAR` | `NO_EDGE` | 已收盘 bar 上没有触发 |
| `SIDE_NOT_ALLOWED_BY_CARD` | `VALIDATION_REJECTED` | 方向与该卡声明不符 |
| `FEATURES_INCOMPLETE` | `DATA_UNAVAILABLE` | 指标末值缺失，无法评估 |
| `BAR_ALREADY_SEEN` | `NO_EDGE` | 同一根 bar 已去重 |
| `SIGNAL_ALREADY_PERSISTED` | `NO_EDGE` | 审计库里已有该信号 |
| `SCAN_EXCEPTION` | `VALIDATION_REJECTED` | 扫描过程中抛异常（已隔离，未污染整轮） |
| `NO_TICKETS_AVAILABLE` | `NO_EDGE` | 轮级：本轮没有可执行票据 |
| `TICKET_SHAPE_INVALID` | `VALIDATION_REJECTED` | 票据结构非法（缺字段/非法周期/非有限数） |
| `TICKET_EXPIRED` | `VALIDATION_REJECTED` | 票据已过期（含无时区时间，fail-closed） |
| `TICKET_EXPIRING_BEFORE_USE` | `VALIDATION_REJECTED` | 票据在有效期内来不及使用 |
| `TICKET_ALREADY_CONSUMED` | `HOLD_EXISTING` | 已递交过订单 / 账本已消费 |
| `TICKET_LEDGER_UNAVAILABLE` | `READINESS_BLOCKED` | 票据账本不可用（损坏），拒绝重复消费 |
| `TICKET_SYMBOL_NOT_IN_SCOPE` | `READINESS_BLOCKED` | 历史票据的标的在白名单外 |
| `ENTRY_ZONE_INVERTED` | `VALIDATION_REJECTED` | `entry_zone_low > entry_zone_high` |
| `SYMBOL_NOT_ALLOWED` | `READINESS_BLOCKED` | 执行期白名单外 |
| `SYMBOL_ALREADY_HELD` | `CHANNEL_CONFLICT` | 同 symbol 已有仓位 |
| `STRATEGY_ALREADY_HELD` | `HOLD_EXISTING` | 同策略已有持仓 |
| `NO_LATEST_PRICE` | `DATA_UNAVAILABLE` | 取不到最新价 |
| `PRICE_OUTSIDE_ENTRY_ZONE` | `NO_EDGE` | 价格不在入场区 |
| `CHANNEL_BUDGET_ZERO` | `READINESS_BLOCKED` | 策略通道名义金额上限为 0（只扫描不下单） |
| `MANAGEMENT_PRIORITY_BUDGET` | `MODEL_DEADLINE` | 本轮研究预算被管理预留吃光 |
| `STRATEGY_TRADER_EXCEPTION` | `VALIDATION_REJECTED` | 建意图抛异常（票据已释放） |
| `PROVIDER_RATE_LIMITED` | `MODEL_RATE_LIMITED` | 供应商限流/冷却（异常分类结果原样带入） |
| `EVIDENCE_GATE_FAILED` | `RESEARCH_INCOMPLETE` | U03 证据门禁整体未放行 |
| `EVIDENCE_DATA_UNAVAILABLE` | `DATA_UNAVAILABLE` | U03 报告里的源取不到 |
| `EVIDENCE_VALIDATION_REJECTED` | `VALIDATION_REJECTED` | U03 报告里的数值/几何拒绝 |

**为什么细分码不算"平行体系"**：分类轴（主因/辅因的取值域）只有九码，由 U05
`DecisionReason` 强制（非九码直接 `UnknownReasonCode`）；细分码只是把"九码之一"
再往下说一层，落在 `DecisionReason.details` 与看板的明细表里。

## 4. 一轮 `no_trade` 的读法

`ScanFunnel.no_open_explanation()`：

```json
{
  "round_id": "2026-09-21T00:00:00+00:00",
  "verdict": "opened | no_edge | blocked | no_candidates",
  "opened": 1, "candidates": 6,
  "primary_reason": "HOLD_EXISTING",
  "reason_codes": ["HOLD_EXISTING", "NO_EDGE", "DATA_UNAVAILABLE"],
  "reasons":   [{"reason": "DATA_UNAVAILABLE", "count": 1}],
  "details":   [{"detail": "MARKET_TRANSPORT_OUTAGE", "reason": "DATA_UNAVAILABLE", "count": 1}],
  "stopped_at": {"market_data_ready": 1, "signal_triggered": 1}
}
```

- `verdict=opened`：本轮**有**开仓意图（`opened` > 0，主因 `HOLD_EXISTING`）；
  `reasons`/`details` 是"其余候选为什么没开"，只是辅因。
- `verdict=blocked`：本轮有闸门级故障（数据/校验/就绪/模型/冲突/研究），
  **不得**读成"没有信号"。
- `verdict=no_edge`：候选都评估过了，确实没有可下单边际。
- `verdict=no_candidates`：本轮没有候选进入漏斗（例如白名单为空）。

`round_explanation()` 再把漏斗、管理优先预算、持仓事实与 U03 证据报告合并，
**复用** U05 的 `classify_cycle` 产出最终 `DecisionReason`。

## 5. 管理优先预算（DL03 / DC10）

`ManagementPriorityPlan` 把一轮预算切成"管理预留池 + 新仓研究池"：

- `claim_management(n)`：可取**全池剩余**，必要时吃掉研究池（管理优先）；
- `claim_research(n)`：只能取"全池剩余 − 管理预留"，**永远**碰不到预留池；
- `research_reason()`：研究池被吃光时给出 `MODEL_DEADLINE` +
  `MANAGEMENT_PRIORITY_BUDGET`，而不是静默地"这轮没信号"。

不变量（测试逐条断言）：`research_used ≤ total − reserve`；
`management_used + research_used ≤ total`；管理侧"已用 + 仍可取"永远 ≥ 预留量。

## 6. 状态文件与读侧

扫描器每轮把紧凑摘要写进 `data/signal_scanner_state.json` 的
`last_scan.funnel`（键名由 `FUNNEL_REPORT_KEY` 定义），并在同级写入
`no_open_reason`（九码主因）与 `no_open_verdict`。

- **向后兼容**：`funnel` 是**新增键**，既有消费者只读自己认识的键。旧状态文件
  （没有 `funnel`）在读侧被显式标成"没有可用漏斗数据"，**不伪造**一份成功漏斗。
- **计数精确、明细截断**：`stopped_at`/`reached`/`reason_codes` 是精确计数；
  逐项明细最多留 `MAX_ITEMS_IN_REPORT` 条并标 `items_truncated`。
- 看板：`GET /funnel`（自包含页面）与 `GET /api/funnel`（JSON）；
  `/channels` 也把 `funnel`/`attribution` 放进模板上下文（模板可选消费）。

## 7. 细分码的来源约定

- 扫描侧细分码由 `src/signal_engine/scanner.py` 写入（共享适配补丁）。
- 票据形状/时效细分码由 `src/core/signal_ticket.py` 的 `ticket_skip_detail()` 产出，
  `valid_signal_ticket()` 是它的薄包装——**扫描侧与执行侧共用同一份真值表**，
  不会出现"扫描说有效、执行说过期"。
- 执行侧细分码由 `src/agents/strategy_trader.py` 写入（共享适配补丁）。
- 依赖：以上三处都从 `core.strategy_funnel` 引用常量，常量**只在漏斗模块登记一次**。
