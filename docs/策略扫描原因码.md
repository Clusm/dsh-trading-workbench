本文档只做三件事——(1) 说明扫描/执行漏斗**每一道闸门**、(2) 登记**细分码 → 九码**

## 1. 为什么需要它（F09 / DL07）

旧口径里一轮扫描只留一个 `status`：

```
last_scan = {"status": "ok"|"error"|"deferred", "tickets": 0, "error_count": 0, ...}
```

`tickets=0` 与 `status=ok` 同时出现时**无法区分**下面这些完全不同的事实：

| 事实 | 旧口径 | 新口径（漏斗） |
|---|---|---|
| 收盘 bar 上确实没有信号 | `ok, tickets=0` | `stopped_at.signal_triggered`, detail `NO_SIGNAL_ON_CLOSED_BAR` / `NO_EDGE` |
| 行情取不到（DNS/限流/预算让步） | 可能仍是 `ok` | `MARKET_TRANSPORT_OUTAGE` / `MARKET_BUDGET_DEFERRED` / `KLINE_FETCH_FAILED` → `DATA_UNAVAILABLE` |
| 策略卡没注册 signal_fn | 只有 `risk_events` 一行告警 | `SIGNAL_FN_MISSING` → `VALIDATION_REJECTED` |
| 标的不在业务开仓白名单 | 被静默过滤 | `SYMBOL_NOT_IN_SCOPE` → `READINESS_BLOCKED`（性质 = 范围界定） |
| 同一根 bar 已经发过信号 | 被 `seen` 静默去重 | `BAR_ALREADY_SEEN` → `NO_EDGE` |
| 有票据但价格不在入场区 | 只在 `reasoning` 自由文本里 | `PRICE_OUTSIDE_ENTRY_ZONE` → `NO_EDGE` |
| 研究预算被管理占用 | 不可见 | `MANAGEMENT_PRIORITY_BUDGET` → `MODEL_DEADLINE` |
| **卡册读不到 / JSON 损坏** | 整轮静默 `tickets=0, status=ok` | **轮级故障** `CARDS_UNAVAILABLE` / `CARDS_INVALID` → `blocked` |
| **策略运行时不可用 / 卡与注册表漂移** | 抛异常，漏斗里**零条记录** | **轮级故障** `STRATEGY_LAB_UNAVAILABLE` / `STRATEGY_LAB_DRIFT` |
| **票据源读取失败** | 与"本轮没有票据"混淆 | **轮级故障** `TICKET_SOURCE_UNAVAILABLE` → `DATA_UNAVAILABLE` |
| **策略通道名义上限为 0（只扫描不下单）** | 循环外早退，状态文件只见"没有票" | **轮级故障** `CHANNEL_BUDGET_ZERO` |
| **所有票都已被消费** | 进循环前被静默过滤 → 读成"没有信号" | 逐票 `TICKET_ALREADY_CONSUMED` → `verdict=handled` |

因此 U08 的硬要求是：**任意一轮 `no_trade`、任意一张有效 ticket 都必须能回答
"为什么没开"，并且"故障"与"真的没有信号"必须可区分**；`status` 只作为机器健康
信号保留（不删、不改语义）。

## 2. 漏斗闸门（K05 README §12 C#13）

枚举在 `core.strategy_funnel.Stage`，顺序 = 评估顺序。每个候选
（`(策略卡, symbol, timeframe)` 三元组，或一张票据）**停在第一道过不去的闸门**。

| # | 闸门 | 类型 | 谁写入 | 含义 |
|---|---|---|---|---|
| 1 | `card_loaded` | 通过型 | 扫描器 | 候选入口（只参与"漏斗收窄"前缀计数） |
| 2 | `card_indicatorized` | 拒绝型 | 扫描器 | 策略卡未指标化（`indicatorized=false`） |
| 3 | `signal_fn_registered` | 拒绝型 | 扫描器 | `signal_fn` 未在内置运行时注册 |
| 4 | `symbol_in_scope` | 拒绝型 | 扫描器 | 非 USDT / 不在业务开仓白名单 / 历史票据标的白名单外 |
| 5 | `timeframe_supported` | 拒绝型 | 扫描器 | 周期不在 `30m/1h/2h/4h/8h/1d` |
| 6 | `market_data_ready` | 拒绝型 | 扫描器 | K 线拉取失败/质量不合格/行数不足/传输故障/预算让步 |
| 7 | `signal_triggered` | 拒绝型 | 扫描器 | 策略函数输出非法、或收盘 bar 无信号、或扫描异常 |
| 8 | `side_allowed` | 拒绝型 | 扫描器 | 方向与该卡 `direction` 不符 |
| 9 | `features_complete` | 拒绝型 | 扫描器 | `adx/rsi/ema/macd/atr` 末值有 NaN |
| 10 | `bar_unseen` | 拒绝型 | 扫描器 | 同一根 bar 已发过信号（去重） |
| 11 | `ticket_emitted` | **通过型** | 扫描器 | 扫描侧全通、票据已落库 |
| 12 | `ticket_active` | **通过型** | 扫描器 | 跨轮/重启恢复出一张仍有效的票据 |
| 13 | `ticket_fresh` | 拒绝型 | 扫描器 / 执行器 | 票据形状非法/过期/来不及使用/已消费 |
| 14 | `no_position_conflict` | 拒绝型 | 执行器 | 同 symbol 或同策略已有仓位（或白名单外） |
| 15 | `price_available` | 拒绝型 | 执行器 | 无最新价 / 建意图失败 |
| 16 | `in_entry_zone` | 拒绝型 | 执行器 | 当前价不在入场区 |
| 17 | `intent_ready` | **通过型** | 执行器 | 终态：真的产出了开仓意图 |

- **通过型闸门**（`card_loaded` / `ticket_emitted` / `ticket_active` / `intent_ready`）
  允许不带细分码，计入 `reached`；**拒绝型闸门必须带细分码**，否则 `FunnelItem`
  直接 `ValueError`（原因不允许缺失）。**反向同样成立**：通过型/终态闸门带细分码
  也直接 `ValueError`——否则它会 `passed=False`，被静默算成"被拒绝"而漏计 `opened`。
- **前置筛 vs 评估型**（`PRE_GATE_STAGES` / `EVALUATION_STAGES`）：闸门 1–5 是
  前置筛（卡册属性与范围界定），闸门 6–17 是评估型。`evaluated` = 到达评估型闸门的
  项数，是 `no_edge` 与 `no_candidates` 的分界线。
- **细分码 ↔ 闸门**（`DETAIL_STAGES`）：每个细分码只能挂在允许的闸门上，挂错即
  `ValueError`。轮级专用码（`ROUND_ONLY_DETAILS`）不得挂候选，只能用
  `record_round_fault()` 登记。
- `stopped_at` 只统计拒绝型闸门（"为什么没开"的直方图）；`reached` 统计通过型
  （`tickets_emitted` / `tickets_recovered` / `opened`）。
- **轮级故障**（`RoundFault`）**不**计入候选数、**不**进闸门直方图，但计入
  `reason_codes`/`details` 与 `round_faults`，因此"这一轮根本没跑成"不再被压成
  `no_edge`/`no_candidates`。

## 3. 细分码 → 九码登记表（含**性质**）

`detail_reason(code)` 是唯一入口；`validate_detail_table()` 自检
"每个细分码都映射到九码"、"九码都有细分码可达"、"每个细分码都登记了性质与闸门"。

**性质**（`DETAIL_NATURE`）决定"这一轮"的结论：

| 性质 | 含义 | 对 verdict 的作用 |
|---|---|---|
| `fault` | 故障：本轮某项能力受损 | 只要出现一个 ⇒ **`blocked`** |
| `edge` | 真的没有边际（候选评估过了） | ⇒ `no_edge` |
| `handled` | 已在处理（已持仓/已消费/同 symbol 冲突） | ⇒ `handled` |
| `scope` | 范围界定/配置态（白名单、未指标化、通道只扫描不下单） | 只做辅因，**不**把整轮变 `blocked` |

| 细分码 | 九码 | 性质 | 允许的闸门 | 语义 |
|---|---|---|---|---|
| `CARD_NOT_INDICATORIZED` | `VALIDATION_REJECTED` | scope | `card_indicatorized` | 该卡未通过"是信号来源"这道配置校验 |
| `SIGNAL_FN_MISSING` | `VALIDATION_REJECTED` | fault | `signal_fn_registered` | 卡与运行时注册表漂移 |
| `SIGNAL_FN_OUTPUT_INVALID` | `VALIDATION_REJECTED` | fault | `signal_triggered` | 策略函数返回形态非法 |
| `SYMBOL_NOT_USDT` | `READINESS_BLOCKED` | scope | `symbol_in_scope` | 非 USDT 标的，不在业务范围 |
| `SYMBOL_NOT_IN_SCOPE` | `READINESS_BLOCKED` | scope | `symbol_in_scope` | 不在业务开仓白名单 |
| `TICKET_SYMBOL_NOT_IN_SCOPE` | `READINESS_BLOCKED` | scope | `symbol_in_scope` | 历史票据的标的在白名单外 |
| `TIMEFRAME_UNSUPPORTED` | `VALIDATION_REJECTED` | fault | `timeframe_supported` | 周期不在支持集合 |
| `MARKET_TRANSPORT_OUTAGE` | `DATA_UNAVAILABLE` | fault | `market_data_ready` | DNS/TLS/限流等整轮传输故障 |
| `MARKET_BUDGET_DEFERRED` | `DATA_UNAVAILABLE` | fault | `market_data_ready` | 受控冷却/预算让步（预期降级） |
| `KLINE_FETCH_FAILED` | `DATA_UNAVAILABLE` | fault | `market_data_ready` | 单标的行情拉取失败 |
| `KLINE_QUALITY_REJECTED` | `DATA_UNAVAILABLE` | fault | `market_data_ready` | K 线质量/最终性不合格 |
| `KLINE_ROWS_INSUFFICIENT` | `DATA_UNAVAILABLE` | fault | `market_data_ready` | 可用收盘 bar 行数不足 |
| `PROVIDER_RATE_LIMITED` | `MODEL_RATE_LIMITED` | fault | `market_data_ready` / `signal_triggered` | 供应商限流/冷却（U05 异常分类结果原样带入） |
| `NO_SIGNAL_ON_CLOSED_BAR` | `NO_EDGE` | edge | `signal_triggered` | 已收盘 bar 上没有触发 |
| `SCAN_EXCEPTION` | `VALIDATION_REJECTED` | fault | `signal_triggered` | 扫描过程中抛异常（已隔离，未污染整轮） |
| `SIDE_NOT_ALLOWED_BY_CARD` | `VALIDATION_REJECTED` | fault | `side_allowed` | 方向与该卡声明不符 |
| `FEATURES_INCOMPLETE` | `DATA_UNAVAILABLE` | fault | `features_complete` | 指标末值缺失，无法评估 |
| `BAR_ALREADY_SEEN` | `NO_EDGE` | edge | `bar_unseen` | 同一根 bar 已去重 |
| `SIGNAL_ALREADY_PERSISTED` | `NO_EDGE` | edge | `bar_unseen` | 审计库里已有该信号 |
| `TICKET_SHAPE_INVALID` | `VALIDATION_REJECTED` | fault | `ticket_fresh` | 票据结构非法（缺字段/非法周期/非有限数） |
| `TICKET_EXPIRED` | `VALIDATION_REJECTED` | fault | `ticket_fresh` | 票据已过期（含无时区时间，fail-closed） |
| `TICKET_EXPIRING_BEFORE_USE` | `VALIDATION_REJECTED` | fault | `ticket_fresh` | 票据在有效期内来不及使用 |
| `TICKET_ALREADY_CONSUMED` | `HOLD_EXISTING` | handled | `ticket_fresh` | 已递交过订单 / 账本已消费 |
| `TICKET_LEDGER_UNAVAILABLE` | `READINESS_BLOCKED` | fault | `ticket_fresh` | 票据账本不可用（损坏 / 取不到跨进程锁 / **写盘失败**），拒绝重复消费。note 里带账本状态（`LEDGER_CORRUPT` / `LEDGER_BUSY` / `LEDGER_WRITE_FAILED`）与底层异常名（如 `OSError`/`PermissionError`） |
| `AUDIT_UNAVAILABLE` | `READINESS_BLOCKED` | fault | `ticket_fresh` | 审计库去重读取抛异常（如 `sqlite3.OperationalError: database is locked`），**无法断定这张票是否已下过单** → fail-closed 跳过（**不是**"已下过单"，也**不是**"没下过"）。note 里带底层异常名；账本未被消费，审计库恢复后下一轮仍可评估 |
| `ENTRY_ZONE_INVERTED` | `VALIDATION_REJECTED` | fault | `ticket_fresh` | `entry_zone_low > entry_zone_high` |
| `SYMBOL_NOT_ALLOWED` | `READINESS_BLOCKED` | scope | `no_position_conflict` | 执行期白名单外 |
| `SYMBOL_ALREADY_HELD` | `CHANNEL_CONFLICT` | handled | `no_position_conflict` | 同 symbol 已有仓位 |
| `STRATEGY_ALREADY_HELD` | `HOLD_EXISTING` | handled | `no_position_conflict` | 同策略已有持仓 |
| `NO_LATEST_PRICE` | `DATA_UNAVAILABLE` | fault | `price_available` | 取不到最新价 |
| `STRATEGY_TRADER_EXCEPTION` | `VALIDATION_REJECTED` | fault | `price_available` | 建意图抛异常（票据已释放） |
| `PRICE_OUTSIDE_ENTRY_ZONE` | `NO_EDGE` | edge | `in_entry_zone` | 价格不在入场区 |
| `NO_TICKETS_AVAILABLE` | `NO_EDGE` | edge | **轮级** | 本轮没有可执行票据（**不是**"票据源读不到"） |
| `CHANNEL_BUDGET_ZERO` | `READINESS_BLOCKED` | scope | **轮级** | 策略通道名义金额上限为 0（只扫描不下单） |
| `RESEARCH_BUDGET_ZERO` | `MODEL_DEADLINE` | fault | **轮级** | 研究预算总额为 0/负（"没有预算可谈"） |
| `MANAGEMENT_PRIORITY_BUDGET` | `MODEL_DEADLINE` | fault | **轮级** | 本轮研究预算被管理预留吃光 |
| `CARDS_UNAVAILABLE` | `READINESS_BLOCKED` | fault | **轮级** | 策略卡册不存在/读不到 |
| `CARDS_INVALID` | `VALIDATION_REJECTED` | fault | **轮级** | 策略卡册存在但不可解析 |
| `STRATEGY_LAB_UNAVAILABLE` | `READINESS_BLOCKED` | fault | **轮级** | 策略运行时注册表/特征模块不可用 |
| `STRATEGY_LAB_DRIFT` | `VALIDATION_REJECTED` | fault | **轮级** | 卡所需 `signal_fn` 与运行时注册表漂移 |
| `TICKET_SOURCE_UNAVAILABLE` | `DATA_UNAVAILABLE` | fault | **轮级** | 票据源读取失败（审计库查询抛错） |
| `ROUND_EXCEPTION` | `VALIDATION_REJECTED` | fault | **轮级** | 轮级未捕获异常（整轮中断时的兜底留痕） |
| `LEDGER_SAVE_DEFERRED` | `READINESS_BLOCKED` | fault | **轮级** | 执行器收尾的**合并落盘**没做成（取不到跨进程锁 / 盘上账本损坏 / **任何写盘异常**如 `OSError`（磁盘满）、`PermissionError`（临时文件被占用））。**不是**"某张票没被消费"：每张票的消费事实在 `consume()` 返回前已单独落盘，这里推迟的是本轮"消费/释放"事实的合并写 |
| `EVIDENCE_GATE_FAILED` | `RESEARCH_INCOMPLETE` | fault | **轮级** | U03 证据门禁整体未放行 |
| `EVIDENCE_DATA_UNAVAILABLE` | `DATA_UNAVAILABLE` | fault | **轮级** | U03 报告里的源取不到 |
| `EVIDENCE_VALIDATION_REJECTED` | `VALIDATION_REJECTED` | fault | **轮级** | U03 报告里的数值/几何拒绝 |

**为什么细分码不算"平行体系"**：分类轴（主因/辅因的取值域）只有九码，由 U05
`DecisionReason` 强制（非九码直接 `UnknownReasonCode`）；细分码只是把"九码之一"
再往下说一层，落在 `DecisionReason.details` 与看板的明细表里。

## 4. 一轮 `no_trade` 的读法

`ScanFunnel.no_open_explanation()`：

```json
{
  "round_id": "2026-09-21T00:00:00+00:00",
  "verdict": "opened | no_edge | handled | blocked | no_candidates | unavailable",
  "opened": 1, "candidates": 6, "evaluated": 5,
  "primary_reason": "HOLD_EXISTING",
  "reason_codes": ["HOLD_EXISTING", "NO_EDGE", "DATA_UNAVAILABLE"],
  "reasons":   [{"reason": "DATA_UNAVAILABLE", "count": 1}],
  "details":   [{"detail": "MARKET_TRANSPORT_OUTAGE", "reason": "DATA_UNAVAILABLE",
                 "nature": "fault", "count": 1}],
  "stopped_at": {"market_data_ready": 1, "signal_triggered": 1},
  "round_faults": []
}
```

- `verdict=opened`：本轮**有**开仓意图（`opened` > 0，主因 `HOLD_EXISTING`）；
  `reasons`/`details` 是"其余候选为什么没开"，只是辅因。
- `verdict=blocked`：本轮有**故障**（性质 `fault`）——数据/校验/就绪/模型/配置。
  **不得**读成"没有信号"。范围界定类码单独出现时也会给 `blocked`（本轮的处理被
  范围/配置挡住且没有任何边际观测）。
- `verdict=no_edge`：候选**评估过**了（`evaluated > 0`），确实没有可下单边际。
- `verdict=handled`：本轮的动作都在"已在处理"（已持仓/已消费/同 symbol 冲突），
  不是"没有信号"，也不是故障。
- `verdict=no_candidates`：一个候选都没**评估**过（全部停在前置筛，或本轮没有候选）。
  主因取当前码里优先级最高者，**不**硬塞 `NO_EDGE`。
  **已知留白（B-r3 N5，P3）**：九码集合冻结在 U05，"候选集为空"**没有**自己的九码，
  因此"本轮一张票都没有"（轮级 `NO_TICKETS_AVAILABLE`，其登记的九码恰好是
  `NO_EDGE`）会得到 `no_candidates` + 主因**字面** `NO_EDGE`。**区分它靠结构化事实、
  不靠主因字符串**：`verdict=no_candidates`（而不是 `no_edge`）＋
  `round_faults[].detail == "NO_TICKETS_AVAILABLE"` ＋ `details` 计数。
  读取方不得只看 `primary_reason` 就断言"本轮没有信号"。
- `verdict=unavailable`：读侧数据不可信（状态文件被篡改/含未登记码/无法解析）。
  此时 `error` 说明原因，`reason_codes` 为空——**不猜**结论。

**判定是唯一的**（`classify_no_open()`）：优先级 故障 > 边际 > 已处理 > 范围界定；
`round_explanation()` 的顶层 `primary_reason`/`verdict` 与内嵌 `no_open` 块
**共用同一次判定**，因此同一份工件不会给出两个互相打脸的结论（B-r1 P0-4c）。

**反向误标已修**：`SYMBOL_NOT_IN_SCOPE` 等范围界定码不再把真实的 `no_edge` 挤成
`blocked`（它们仍如实出现在辅因里，但不抢主因）。

`round_explanation()` 再把漏斗、管理优先预算、持仓事实与 U03 证据报告合并，
**复用** U05 的 `classify_cycle` 产出最终 `DecisionReason`。

## 5. 管理优先预算（DL03 / DC10）

`ManagementPriorityPlan` 把一轮预算切成"管理预留池 + 新仓研究池"：

- `claim_management(n)`：可取**全池剩余**，必要时吃掉研究池（管理优先）；
- `claim_research(n)`：只能取"全池剩余 − 管理预留"，**永远**碰不到预留池；
- `research_reason()`：研究池被吃光时给出 `MODEL_DEADLINE` +
  `MANAGEMENT_PRIORITY_BUDGET`；总预算为 0/负时给出 `MODEL_DEADLINE` +
  `RESEARCH_BUDGET_ZERO`（"没有预算可谈"与"预算被管理占用"是两件事），
  都不是静默地"这轮没信号"；
- `meets_management_demand()`：管理侧**每一次请求都拿到了它要的量**时才是 `True`
  （按累计 `management_shortfall` 判定）。

不变量（测试逐条断言）：`research_used ≤ total − reserve`；
`management_used + research_used ≤ total`；管理侧"已用 + 仍可取"永远 ≥ 预留量。
**注意**："研究取用不减少管理可取用的量"**不是**本模块的不变量（研究取用自然减少
全池剩余）——真正的承诺是"研究碰不到预留池"。

## 6. 状态文件与读侧

扫描器每轮把紧凑摘要写进 `data/signal_scanner_state.json` 的
`last_scan.funnel`（键名由 `FUNNEL_REPORT_KEY` 定义），并在同级写入
`no_open_reason`（九码主因）与 `no_open_verdict`。

- **向后兼容**：`funnel` 是**新增键**，既有消费者只读自己认识的键。旧状态文件
  （没有 `funnel`）在读侧被显式标成"没有可用漏斗数据"（`available=False`），
  **不伪造**一份成功漏斗。
- **不可信输入**：被篡改/含未登记码的状态文件在读侧 fail-closed ——
  `funnel_from_report()` 丢弃未登记条目并置 `report_corrupt_reason`，
  此后 `no_open_explanation()` 返回 `verdict=unavailable`，**不抛异常**，
  因此一个坏状态文件不会把展示层打成 500。
- **计数精确、明细截断**：`stopped_at`/`reached`/`reason_codes`/`round_faults`/
  `evaluated` 是精确计数；逐项明细最多留 `MAX_ITEMS_IN_REPORT` 条并标
  `items_truncated`。
- 看板：`GET /funnel`（自包含页面）与 `GET /api/funnel`（JSON）；
  `/channels` 也把 `funnel`/`attribution` 放进模板上下文（模板可选消费）。

## 7. 细分码的来源约定

- 扫描侧细分码由 `src/signal_engine/scanner.py` 写入（共享适配补丁）；卡册/
  运行时的**轮级故障**也由它用 `record_round_fault()` 登记。
- 票据形状/时效细分码由 `src/core/signal_ticket.py` 的 `ticket_skip_detail()` 产出，
  `valid_signal_ticket()` 是它的薄包装——**扫描侧与执行侧共用同一份真值表**，
  不会出现"扫描说有效、执行说过期"。
- 执行侧细分码由 `src/agents/strategy_trader.py` 写入（共享适配补丁）；
  通道预算为 0 用 `record_round_fault(CHANNEL_BUDGET_ZERO)` 登记。
- 依赖：以上三处都从 `core.strategy_funnel` 引用常量，常量**只在漏斗模块登记一次**；
  细分码挂错闸门或未登记性质都会在导入/登记处 fail-closed。
