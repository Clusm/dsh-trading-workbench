# Binance 行情接入与 418 治理

日期：2026-09-14

## 目标与边界

本次整改只改变 Binance 数据接入和调度方式，不改变风险档、资金基线、杠杆上限、
策略阈值、20币 USD-M 永续白名单、Guardian 影子状态或 Web3 执行权重。

治理目标：

- 正常运行不再出现 HTTP 429/418；
- 任一调用方命中限流后，所有公共 REST 调用统一停手；
- WebSocket 断线不能触发 REST 请求风暴；
- 行情不可证明新鲜时禁止把陈旧数据作为新开仓证据；
- 账户、持仓、保护单和退出管理始终高于扫描和只读情报。

## 架构

`data.binance_transport` 是唯一公共 REST 发送入口。它根据端点和参数计算权重，串行完成
发送与限流响应登记，并读取 `X-MBX-USED-WEIGHT-1M` 校正本地预算。

`data.rate_limit` 保存进程级预算和跨重启冷却：

- 本地默认只使用 600 weight/min；
- Binance USD-M 基线额度为 2400 weight/min；
- 实际用量达到 75% 时延后后台情报；
- 达到 90% 时延后所有非关键公共请求；
- 429 尊重 `Retry-After` 并停止重试；
- 418 在完整封禁窗口内不发送探测请求。

`data.price_stream` 使用 2026 年新版路由：

- `/market`：ticker、markPrice、1m/15m K线；
- `/public`：bookTicker；
- 两条连接独立退避，bookTicker 失败不会拖垮K线与价格流；
- 首帧超时和数据年龄共同判定连接是否真正供数。

`data.market_stream_cache` 只在请求标的全部新鲜时返回完整快照，不混用新旧数据。
`data.kline_store` 首次回补历史，之后由 WebSocket 更新，并从15m增量聚合
1h/2h/4h/8h/1d；断线时只查询缺失区间，并把快照原子保存到 `data/cache/klines`。

## 流量优先级

| 级别 | 数据 | 处理原则 |
|---|---|---|
| P0 | 平仓、撤单、保护单 | 预留执行能力，不与情报竞争 |
| P1 | 当前持仓和订单对账 | 高频但使用短缓存和私有流 |
| P2 | 策略扫描和AI按需行情 | 按K线闭合和查询预算调度 |
| P3 | Top Trader、市场广度等影子情报 | 高水位或冷却时直接跳过本轮 |

## 故障状态

1. WebSocket 正常：所有高频行情命中推送缓存。
2. WebSocket 陈旧：网关保留带年龄的最后快照，只进行受控增量 REST 回补。
3. HTTP 429：记录服务端冷却，后台与普通公共请求立即短路。
4. HTTP 418：持久化硬冷却，服务重启也不得提前探测。
5. 行情不可用：停止产生依赖新行情的新开仓证据；存量仓位继续由交易所保护单和账户流管理。

## 配置

`config/settings.yaml` 的 `binance_market_data` 保存本地预算和流配置。生产运行必须使用
稳定、独立的出口 IP；共享代理节点上的其他程序或用户同样会消耗 Binance 的 IP 配额，
软件内部限流无法替外部流量提供保证。
