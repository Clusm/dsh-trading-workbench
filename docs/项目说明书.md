# multi-agent-trader 项目说明书

> 面向第一次接触本项目的人：先讲清楚它是什么、能做什么、怎么用、什么时候不能用
> 最后更新：2026-09-01
> 适用版本：截至 2026-09-01（H 级已修复 11 项；M 级 7 项待办）

---

## 1. 一句话简介

**multi-agent-trader** 是一个跑在本地 Windows 上的多 Agent 加密货币实验平台：它把"做交易决策"这件事拆成多个 Agent 并行干活，然后由确定性闸门审核、由币安 USDⓈ-M Demo Trading 执行；所有决策、所有订单、所有风控拦截全部落库，次日自动生成复盘报告。

它的当前阶段是 **phase 4**（Demo Trading 已联通，OpenCode Zen LLM 已接入，Tool Call 已就位）。

---

## 2. 这个项目要解决什么

绝大多数"AI 交易"项目只有一段 prompt：让 LLM 输出一段文本、解析后下单。这类项目有三个常见坑：

1. **幻觉**：LLM 算指标、算仓位、算止损，准确率很差。
2. **无复盘**：成交后无法回答"当时为什么买、当时忽略了什么"。
3. **无风控**：单笔大亏触发爆仓，没有熔断、没有"只能平不能开"的隔离。

multi-agent-trader 围绕这三个坑做设计：

- **指标计算交给确定性代码**（K 线 → pandas → signal_fn），LLM 只看摘要、做综合判断。
- **每个 Agent 的输入/输出全部留底**，复盘时能精确回答"哪条信息误导了主 Agent"。
- **确定性闸门三道**（Pydantic 校验、ActionSpace、Risk Agent 规则），LLM 解释文本不影响放行/拒绝。

---

## 3. 它不是什么 / 不做什么

- ❌ 不是自动赚钱机器；明确"不保证盈利"。
- ❌ 不是实盘交易系统；默认走 Binance Demo Trading（主网真实行情 + 虚拟资金），`live` 档位保留但默认禁用。
- ❌ 不是高频/做市系统；节奏是慢循环 10 分钟 + 快循环 30 秒。
- ❌ 不是公开教程项目；本项目性质是"个人实战学习项目"，不写对外文档（除本说明书与技术报告）。
- ❌ 不让 LLM 直接执行任意 Python；只允许调用已注册的白名单工具（行情查询、提交决策、查询复盘库）。

## 4. 关键概念

### 4.1 双交易通道

| 通道 | 谁决策 | 信号来源 | 杠杆档 | 保证金上限 | 默认逐仓 | 风控特殊规则 |
|---|---|---|---|---|---|---|
| `strategy` | `strategy_trader`（LLM） | `SignalScanner` 扫描 strategy_lab final 策略卡 | 1–20x | 通道权益 × 0.80 | 否 | 只能交易卡片中的 symbol/周期/方向；SL/TP 与卡片一致 |
| `ai` | `ai_trader`（LLM + 工具调用） | 完全自主判断 | 常规 20x / 强信心 25x | 通道权益 × 0.80 | **是** | 单笔风险 ≤ AI 权益 × 2%；当日 -30% 熔断 |

两通道共用同一份 `Risk Agent` 与 `Execution Agent`，但**资金、统计、熔断、订单归属、保证金上限完全独立**。

### 4.2 固定 200U 会话资金

无论你往币安 Demo 充多少虚拟金（通常是 5000U），系统内部都按 **200U 会话权益** 计量；亏到 ≤ 1U 自动全平并重置回 200U。

- paper 模式：baseline = 0，session_equity = 账本现金。
- demo/testnet 模式：baseline = 交易所余额 − 200，session_equity = 真实账户波动 − 200。
- **关键不变量**：风控、AI 看到的是 200U；与币安账户容器解耦。

### 4.3 三道确定性闸门

按顺序：

1. **Pydantic Schema 校验**：模型必须通过 `submit_decision` 工具提交，格式错误直接拒绝；裸 JSON 也会被 `check_decision` 兜底（H3 修复）。
2. **ActionSpace.check_intent**：复用同一份谓词做运行时复核（避免"schema 说合法、闸门却拒"的漂移）。
3. **Risk Agent 规则**：纯 Python 规则（杠杆、保证金、SL/TP、重复单、行情过期、AI 当日熔断）。

LLM 只能"生成解释文本"，无法绕开任何一道闸门。

### 4.4 行情覆盖

- Top 40 USDT 永续，每标的 1m×600（10 小时）+ 15m + 1h K 线，含 ATR / 量能 / 资金费率 / OI。
- 主 Agent 支持 Tool Call：可主动查询任意 USDT 永续 1m/5m/15m/1h/4h/1d K 线 + ATR + 量能 + 资金费率 + OI，也可查询 Top 活跃合约。
- 单轮查询预算 8 次（token 闸门；orchestrator 占全系统 prompt token 的 95%）。

### 4.5 交易目标（软目标，非强制）

- 每小时短线 5 笔。
- 每日小时级 3 笔。

**系统不强制开单**；品种、方向、数量、杠杆全部由主 Agent 自主决策。

## 6. 快速开始

### 6.1 环境要求

- Windows + Python 3.11+（推荐 3.13）。
- PowerShell（自带）。
- 一个币安 Demo Trading 账号（免费，1 分钟注册）。

### 6.2 安装

```powershell
cd C:\Users\Tao\Desktop\币安\multi-agent-trader
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
```

### 6.3 配置

复制 `.env.example` 为 `.env`：

```powershell
copy .env.example .env
```

编辑 `.env`（缺哪补哪）：

```ini
# OpenCode Zen（默认 LLM 网关）—— 没有也能跑，会自动回退 Mock
OPENCODE_API_KEY=
OPENCODE_BASE_URL=https://tokenrhythm.studio/v1
OPENCODE_MODEL=glm-5.3-flash

# 执行环境：paper / demo / testnet / live
EXECUTION_MODE=demo

# Binance Demo Trading：主网真实行情 + 虚拟资金
# 在 https://demo.binance.com 的 API Management 创建
BINANCE_DEMO_API_KEY=
BINANCE_DEMO_API_SECRET=

# 可选：Tavily 网页搜索
TAVILY_API_KEY=
# 可选：Etherscan 免费层
ETHERSCAN_API_KEY=
```

> **小贴士**：没有 OpenCode key 时，LLM 走 Mock，所有 Agent 仍能跑通主流程（情报简报、信号、风控、执行、复盘），只是决策内容是占位。

### 6.4 跑一次（冒烟测试）

```powershell
.venv\Scripts\python.exe scripts\run_phase1.py
```

预期输出（节选）：


### 6.5 持续运行



## 7. 控制台使用

### 7.1 页面

| 路径 | 用途 |
|---|---|
| `/` | 总览：会话权益 / 通道卡片 / 当前持仓 / 最近决策 |
| `/agents` | 各 Agent 最近运行与 token 用量 |
| `/trades` | 订单与成交 |
| `/reviews` | 复盘报告（所有 `<details>` 默认展开） |
| `/channels` | 双通道独立卡片（资金 / 保证金 / 当日盈亏） |
| `/events` | 风控事件流 |

### 7.2 控制接口

| 接口 | 行为 |
|---|---|
| `POST /api/control` `{"state": "normal"}` | 恢复正常 |
| `POST /api/control` `{"state": "pause"}` | 阻断新开仓 |
| `POST /api/control` `{"state": "close_only"}` | 只允许 close/reduce |
| `POST /api/control` `{"state": "emergency"}` | `broker.close_all()` + 记 critical 事件 |
| `POST /api/cycle/run` | 手动触发一轮 |
| `POST /api/capital/reset` | 仅测试模式可用；**实盘模式被拒** |
| `POST /api/mode` `{"mode": "demo\|live"}` | 保存到 `.env`，重启生效 |

### 7.3 控制台模式下拉

只显示「模拟盘 / 实盘」；`paper / testnet` 仍作为后端兜底保留（缺 key 时回退）。

### 8.2 `config/agents.yaml`

每个 Agent 独立配模型 / 温度 / token / `reasoning_effort`。主 Agent 是 `ai_trader`，主模型默认 `qwen3.7-max`（`reasoning_effort: high`）；其他 Agent 用 `qwen3.7-flash`。

### 8.3 `config/risk_learning.yaml`

学习冒险档（默认已开启）。`strong_*` 是强信心档：仅当 `confidence >= 0.75` 且带止损才生效。

## 9. 风险档位

### 9.1 学习冒险档（默认）

| 项 | 常规档 | 强信心档 |
|---|---|---|
| max_leverage | 20x | 50x |
| max_margin_usage | 0.80 | 0.95 |
| max_position_notional | 100,000U | 200,000U |
| max_open_positions | 8 | 8 |
| max_risk_per_trade | 2% | 2% |
| daily_loss_stop | 15% | — |
| max_drawdown_from_peak | 30% | — |
| allow_bare_position | true | — |

### 9.2 AI 通道特殊档

- max_leverage：常规 20x / 强信心 25x。
- 默认逐仓（`margin_mode=ISOLATED`）。
- 强制 SL/TP（`allow_bare_position: false`）。
- 当日 -30% 熔断。
- 单笔风险 ≤ AI 权益 × 2%。

### 9.3 永不关闭的硬规则

- 所有减仓/平仓订单强制 `reduceOnly`。
- 同一决策周期内不得重复发相同方向订单（幂等 `clientOrderId`）。
- API Key 永不开启提现权限（币安 API 本身也要求 key 关闭提现）。
- 行情过期、账户状态无法核对时，不新开仓。
- 人工可在任何时刻切到 `pause` / `close_only` / `emergency`。

## 10. 复盘机制

### 10.1 自动复盘

- UTC 00:05 之后，慢循环检测到即自动生成昨日复盘报告。
- 最多回填最近 7 天的缺口。
- 重启不会重复跑（按 `daily_reviews` 表的 `review_date` 判重）。

### 10.2 复盘内容

- 交易归因：判断错误 / 执行问题 / 数据问题 / 风控拦截正确 / 市场随机。
- 每个 Agent 的贡献评分与错误清单。
- 主 Agent 引用策略库后的实际表现。
- AI 通道单独统计，与策略通道分离。
- 明日注意事项。

### 10.3 手动复盘

```powershell
.venv\Scripts\python.exe scripts\run_review.py
```

报告位置：`data/reviews/YYYY-MM-DD.md`。

## 11. 审计与日志

### 11.1 SQLite

`data/agent_trader.sqlite`：

| 表 | 作用 |
|---|---|
| `agents` / `agent_runs` | Agent 名称、版本、每次运行（起止时间、状态、模型、token、估算成本、延迟） |
| `artifacts` / `llm_calls` / `tool_calls` | 每个 Agent 输出的结构化 JSON + sha256；LLM 完整 prompt/response + 工具调用 |
| `trade_decisions` / `trade_intents` | 主 Agent 每轮决策；每个交易意图全字段 + 状态流转 |
| `risk_verdicts` | 风控放行/拒绝/降额及原因 |
| `orders` / `positions` / `portfolio_snapshots` | clientOrderId、交易所单号、成交、状态；当前与历史仓位；权益快照 |
| `signal_events` / `signal_tickets` | 信号触发、ticket 状态 |
| `decision_conflicts` | 通道冲突（如 AI 单与策略单同 symbol） |
| `channel_daily_stats` / `daily_rebalances` | 双通道每日统计、6:4 重算 |
| `risk_events` / `daily_reviews` / `agent_scorecard` | 熔断/断线/异常、人工干预；每日复盘；Agent 滚动评分 |

### 11.2 JSONL 原始日志

- `data/logs/YYYY-MM-DD/{agent}.jsonl`：每个 Agent 的输入/输出/错误。
- `data/logs/YYYY-MM-DD/llm_raw.jsonl`：完整 prompt/completion。

### 11.3 每笔交易必答 5 问

1. 当时哪些 Agent 提供了什么信息？
2. 主 Agent 引用了哪张策略卡？为什么？
3. 风控是放行、降额还是拒绝？
4. 订单从发出到成交用了多久？实际价差多少？
5. 最终盈亏应归因到哪里？

## 12. 常见操作

### 12.1 切换执行模式

1. 改 `.env` 的 `EXECUTION_MODE`（或在控制台 `/api/mode`）。
2. 重启 `scripts/run_web.py` 或 `scripts/run_phase1.py`。
3. 缺 key 时自动回退 `paper`，并在 `risk_events` 记 `broker_fallback_paper` 警告。

### 12.2 重置资金（仅测试模式）

- 控制台：`POST /api/capital/reset`（实盘模式被拒）。
- CLI：无直接命令；删除 `data/capital_state.json` 并重启，或在 `service.py` 调 `capital.manual_reset()`。

重置后 `session_equity` 回到 500U（demo 模式实际为 200U，因 `initial_equity` 已升级为 500；详见 `CHANGES_2026-09-01.md` F1 修复）。

### 12.3 紧急平仓

控制台右上角 → `emergency` 按钮，或 `POST /api/control` `{"state": "emergency"}`：

- `broker.close_all()` 一次性平掉所有通道、所有 symbol。
- 记 `manual_emergency_close` (critical) 事件。
- 实盘模式同样适用（如果你真的在 live 跑）。

### 12.4 切换到强信心档

- 编辑 `config/risk_learning.yaml` 的 `strong_*` 字段。
- 触发条件：模型在 `submit_decision` 中给 `confidence >= 0.75` **且** 提交了 `stop_loss`。
- AI 通道强信心档上限是 25x（不是 `strong_max_leverage: 50`），由 `ai_strong_max_leverage: 25` 限定。

### 12.5 调慢循环节奏

`config/settings.yaml`：

```yaml
decision_cycle:
  interval_minutes: 10       # 慢循环
  fast_interval_seconds: 30  # 快循环
  query_budget: 8            # 主 Agent 每轮工具调用预算
```

`scripts/run_phase1.py --loop --interval-minutes 5` 临时覆盖。

### 12.6 调整双通道权重

`config/settings.yaml`：

```yaml
channels:
  strategy_weight: 0.6
  ai_weight: 0.4
```

次日 UTC 00:00 自动重平衡；如需立即生效，手动调 `ChannelManager._rebalance_if_needed()` 或重置通道状态。

## 13. 故障排查

### 13.1 "phase1 start" 后立即退出 / 没有 run 输出

- 检查 `OPENCODE_API_KEY`：缺 key 时 LLM 走 Mock，仍能跑；如完全无输出，多半是 LLM 抛错导致 `run_one_cycle` 异常。
- 看 `data/agent_trader.sqlite → risk_events` 最近 `cycle_error` 事件。

### 13.2 控制台 500 / 502

- 慢循环或快循环异常未兜住。检查 `risk_events` 表 `cycle_error` / `fast_cycle_error`。
- 重启 `scripts/run_web.py`。

### 13.3 余额显示 5000U（demo 模式）

- 旧版 bug：手动重置时 `baseline` 被强制设 0；已修（F1，2026-09-01）。
- 升级到最新代码 + 删除 `data/capital_state.json` 即可。

### 13.4 通道资金不随会话权益变化

- 旧版 bug：`_channel_day_start()` 优先返回陈旧存储值；已修（F2）。
- 升级代码即可。

### 13.5 重置后页面仍显示旧值

- 旧版 bug：`_latest` 缓存未刷新；已修（F4），重置后控制台立即刷新。
- 升级代码即可。

### 13.6 保护单没挂上

- 实盘执行层若挂不上止盈/止损必须重试；仍失败则立即平掉该仓位（`M1` 待办：纸面加仓路径只能收紧不能放宽）。
- 看 `risk_events` 表 `futures_min_qty_skip` / `futures_leverage_error` / `futures_fill_unconfirmed`。

### 13.7 Token 暴涨、模型反复重试

- 多半是 schema 与运行时闸门漂移；2026-09-01 已统一到 `ActionSpace`（一处定义，三处复用）。
- 如果还出现：看 `data/logs/YYYY-MM-DD/llm_raw.jsonl`，找 `submit_decision` 校验失败的 tool result。

### 13.8 没有任何 ticket

- `SignalScanner` 静默：`signal_scanner_config.strategy_lab_src` 路径错、或 `strategy_cards.json` 缺 `indicatorized: true` 卡片。
- 临时关 universal 扫描：`signal_scanner.universal_cards: false`，仅扫卡片自带 symbol。

## 14. 限制与已知问题

### 14.1 M 级（中危）待办

| # | 现象 | 计划 |
|---|---|---|
| M1 | PaperBroker 加仓路径无条件覆盖旧 SL/TP | 改为"只能收紧不能放宽" |
| M2 | Paper 盈亏不计手续费 | 加手续费模型 |
| M3 | LLM 客户端零重试 | 加 `tenacity` 重试 |
| M4 | validator 与风控闸门价格来源不一致 | 统一从 `state.execution_prices` 拿 |
| M5 | `_position_margin` 2s 缓存导致新仓 margin 记 0/旧值 | 缓存 key 加 timestamp + TTL |
| M6 | `equity()/available_cash()` 异常吞掉返回 0 | 显式抛错 |
| M7 | `close_all` 破产路径订单来源归属待确认 | 按仓位 ledger 强写来源 |

### 14.2 实盘切换尚未验证

- `live` 档位保留但**默认禁用**；切换到实盘前必须重新确认风控档位（`real_learning.yaml` 草案见 `开发规格书_v2.md` §6.2）。
- 没有自动化测试覆盖 `BinanceFuturesBroker` 在生产环境的容错。

### 14.3 不适合

- 高频/做市（慢循环 10 分钟 + 快循环 30 秒）。
- 大资金（默认杠杆 20x、单笔 100,000U 上限是 demo 量级）。
- 多用户（无认证，监听 `127.0.0.1`）。
