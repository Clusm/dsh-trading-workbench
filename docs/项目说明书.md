# multi-agent-trader 项目说明书

> 面向第一次接触本项目的人：先讲清楚它是什么、能做什么、怎么用、什么时候不能用
> 最后更新：2026-09-16
> 适用版本：Demo/live 双进程双账本、实盘接管安全链、WorkBuddy 受限决策适配器

---

## 1. 一句话简介

**multi-agent-trader** 是一个跑在本地 Windows 上的多 Agent 加密货币合约系统：它把
“做交易决策”拆成多个 Agent 协作，再由确定性闸门审核，可在隔离的 Demo 和 live profile
中执行币安 USDⓈ-M 永续交易；所有决策、订单和风控拦截均落库并进入复盘。

当前版本已同时运行 Demo `:8000` 与 live `:8001`，两者账本、状态、日志和备份隔离；
账户/订单镜像与 Web3 情报仍保持观察或影子权限。实盘上线成熟度继续由发布门禁和观察证据
判断，服务能运行不等于正式发布门槛已经满足。

---

## 2. 这个项目要解决什么

绝大多数"AI 交易"项目只有一段 prompt：让 LLM 输出一段文本、解析后下单。这类项目有三个常见坑：

1. **幻觉**：LLM 算指标、算仓位、算止损，准确率很差。
2. **无复盘**：成交后无法回答"当时为什么买、当时忽略了什么"。
3. **无风控**：单笔大亏触发爆仓，没有熔断、没有"只能平不能开"的隔离。

multi-agent-trader 围绕这三个坑做设计：

- **指标计算交给确定性代码**（K 线 → pandas → signal_fn），LLM 只看摘要、做综合判断。
- **每个 Agent 的输入/输出全部留底**，复盘时能精确回答"哪条信息误导了主 Agent"。
- **确定性闸门三道**（Pydantic 校验、ActionSpace、Risk Agent 规则），LLM 解释文本不影响放行/拒绝。

---

## 3. 它不是什么 / 不做什么

- ❌ 不是自动赚钱机器；明确"不保证盈利"。
- ❌ 不是已经完成收益验证的成熟产品；虽然 live 通道已经接入，小额运行也不能替代
  7 天观察、200 个方向候选和 30 笔闭合 Demo 交易门槛。
- ❌ 不是高频/做市系统；节奏是慢循环 10 分钟 + 快循环 30 秒。
- ❌ 不是公开教程项目；本项目性质是"个人实战学习项目"，不写对外文档（除本说明书与技术报告）。
- ❌ 不让 LLM 直接执行任意 Python；只允许调用已注册的白名单工具（行情查询、提交决策、查询复盘库）。

## 4. 关键概念

### 4.1 双交易通道

| 通道 | 谁决策 | 信号来源 | 杠杆档 | 保证金上限 | 默认逐仓 | 风控特殊规则 |
|---|---|---|---|---|---|---|
| `strategy` | `strategy_trader`（LLM） | `SignalScanner` 扫描 strategy_lab final 策略卡 | 1–20x | 通道权益 × 0.90 | 否 | 只能交易卡片中的 symbol/周期/方向；SL/TP 与卡片一致 |
| `ai` | `ai_trader`（LLM + 工具调用） | 完全自主判断 | 常规 20x / 强信心 25x | 通道权益 × 0.90 | **是** | 普通档风险 ≤ AI 权益 × 2%；有界强信心档风险 ≤ 10%；当日 -30% 熔断 |

两通道共用同一份 `Risk Agent` 与 `Execution Agent`，但**资金、统计、熔断、订单归属、保证金上限完全独立**。

### 4.2 分 profile 资金基线

Demo/testnet 仍按 **500U 会话权益**计量；live 在首次接管时以真实账户权益建独立基线，
不得继承 Demo 的 500U 口径，也不得因测试脚本或模式切换重写实盘状态。

- paper 模式：baseline = 0，session_equity = 账本现金。
- demo/testnet 模式：baseline = 交易所权益 − 500，session_equity = 交易所权益 − baseline。
- live 模式：`initial_equity` 等于接管时真实权益，`anchor_source=live_account_equity`。
- **关键不变量**：每个 profile 只读取自己的资金状态；live 不得套用 Demo 基线。

### 4.3 三道确定性闸门

按顺序：

1. **Pydantic Schema 校验**：模型必须通过 `submit_decision` 工具提交，格式错误直接拒绝；裸 JSON 也会被 `check_decision` 兜底（H3 修复）。
2. **ActionSpace.check_intent**：复用同一份谓词做运行时复核（避免"schema 说合法、闸门却拒"的漂移）。
3. **Risk Agent 规则**：纯 Python 规则（杠杆、保证金、SL/TP、重复单、行情过期、AI 当日熔断）。

LLM 只能"生成解释文本"，无法绕开任何一道闸门。

### 4.4 行情覆盖

- 市场与交易范围限定为配置中的 20 个币安 USD-M、USDT 本位数字货币永续白名单；按快速池和全量池轮转采集。
- 主 Agent 支持 Tool Call：可主动查询任意 USDT 永续 1m/5m/15m/1h/4h/1d K 线 + ATR + 量能 + 资金费率 + OI，也可查询 Top 活跃合约。
- AI 单轮查询预算 4 次，用于约束上下文膨胀和上游网关超时。

### 4.5 交易目标（软目标，非强制）

- 每小时短线 5 笔。
- 每日小时级 3 笔。

**系统不强制开单**；品种、方向、数量、杠杆全部由主 Agent 自主决策。

## 6. 快速开始

### 6.1 环境要求

- Windows + Python 3.11+（推荐 3.13）。
- PowerShell（自带）。
- 一个币安 Demo Trading 账号（免费，1 分钟注册）。

### 6.2 安装

```powershell
cd <项目根目录>
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
```

### 6.3 配置

复制 `.env.example` 为 `.env`：

```powershell
copy .env.example .env
```

编辑 `.env`（缺哪补哪）：

```ini
# SenseNova OpenAI 兼容网关——建议写入不跟踪的 .env.local
SENSENOVA_API_KEY=
SENSENOVA_BASE_URL=https://token.sensenova.cn/v1
SENSENOVA_MODEL=deepseek-v4-flash

# 执行环境：paper / demo / testnet / live
EXECUTION_MODE=demo

# Binance Demo Trading：主网真实行情 + 虚拟资金
# 在 https://demo.binance.com 的 API Management 创建
BINANCE_DEMO_API_KEY=
BINANCE_DEMO_API_SECRET=

# 可选：Tavily 网页搜索
TAVILY_API_KEY=
# 可选：Etherscan 免费层
ETHERSCAN_API_KEY=
```

> **小贴士**：默认 SenseNova 路径没有有效 key 时，LLM 走 Mock；显式启用 WorkBuddy 时，
> `ai_trader` 改用其内置模型。两种路径都不影响确定性风控和离线冒烟测试。

### 6.4 跑一次（冒烟测试）

```powershell
.venv\Scripts\python.exe scripts\run_phase1.py
```

预期输出（节选）：

```text

============================================================
run_id: 4c5a...

```

### 6.5 持续运行

```powershell
# 每 10 分钟跑一轮慢循环 + 每 30 秒跑一轮快循环
.venv\Scripts\python.exe scripts\run_phase1.py --loop

# 自定义慢循环间隔
.venv\Scripts\python.exe scripts\run_phase1.py --loop --interval-minutes 5
```

### 6.6 生成每日复盘

```powershell
.venv\Scripts\python.exe scripts\run_review.py
```

### 6.7 启动本地控制台（推荐）

```powershell
.venv\Scripts\python.exe scripts\run_web.py
# 浏览器打开 http://127.0.0.1:8000
```

后台默认每 10 分钟跑一轮慢循环 + 每 30 秒跑一轮快循环。控制台可手动触发一轮、切暂停/紧急平仓、切执行模式、看双通道资金/收益。

## 7. 控制台使用

### 7.1 页面

| 路径 | 用途 |
|---|---|
| `/` | 总览：会话权益 / 通道卡片 / 当前持仓与敞口 / 运行控制 |
| `/decisions` | 交易（决策中心）：情报 → 策略匹配 → 调度 → 拍板 → 执行的决策链 |
| `/orders` | 订单与成交、仓位流水、资金快照（旧 `/trades` 已 302 重定向至此） |
| `/events` | 风控事件流 |
| `/reviews` | 复盘报告（所有 `<details>` 默认展开） |
| `/agents` | 各 Agent 最近运行与 token 用量 |
| `/channels` | 双通道独立卡片（资金 / 保证金 / 当日盈亏） |

导航按使用频率排列：现状 → 决策 → 执行 → 风险 → 复盘，运维视角页面后置。
数字键 `1`-`7` 可直接切页，`R` 刷新。

### 7.2 控制接口

| 接口 | 行为 |
|---|---|
| `POST /api/control` `{"state": "normal"}` | 恢复正常 |
| `POST /api/control` `{"state": "pause"}` | 阻断新开仓 |
| `POST /api/control` `{"state": "close_only"}` | 只允许 close/reduce |
| `POST /api/control` `{"state": "emergency"}` | `broker.close_all()` + 记 critical 事件 |
| `POST /api/cycle/run` | 手动触发一轮 |
| `POST /api/capital/reset` | 仅测试模式可用；**实盘模式被拒** |
| `POST /api/mode` `{"mode": "demo\|live"}` | 保存到 `.env`，重启生效 |

### 7.3 控制台模式下拉

只显示「模拟盘 / 实盘」；`paper / testnet` 仍作为后端兜底保留（缺 key 时回退）。

| `quotas` | `hourly_short_target: 5`, `daily_hourly_target: 3` | 软目标 |
| `signal_scanner` | `kline_limit: 300`, `ticket_valid_bars: 2`, `universal_cards: false`, `max_scan_symbols_per_cycle: 5` | 内置确定性策略运行时；仅执行策略卡已验证品种；通用模式按游标轮转 |
| `decision_cycle` | `interval_minutes: 10`, `fast_interval_seconds: 30`, `query_budget: 4` | 循环节奏 |
| `symbol_universe` | `top_n: 20`, `analyze_top: 10`, `quote_asset: USDT` | 行情标的池 |
| `market_universe` | `core_symbols`, `quick_core_top`, `quick_anomaly_top`, `full_top_n`, `full_anomaly_n`, `short_move_pct: 3.0` | 动态扫描池 |

### 8.2 `config/agents.yaml`

每个 Agent 独立配置温度、输出 token 和 `reasoning_effort`。默认路径使用 SenseNova 的
`deepseek-v4-flash`；设置 `MTA_AI_DECISION_PROVIDER=workbuddy` 时，仅 `ai_trader` 改用
WorkBuddy 内置 `deepseek-v4.1-flash`，其余节点继续使用默认路径。Risk/Execution 为
确定性代码，不调用 LLM。

### 8.3 `config/risk_learning.yaml`

学习冒险档（默认已开启）。有界强信心档要求 `confidence >= 0.65`、有效止损止盈且实际
风险收益比 `RR >= 2`；条件不足时只能使用常规档。

## 9. 风险档位

### 9.1 学习冒险档（默认）

| 项 | 常规档 | 强信心档 |
|---|---|---|
| max_leverage | 20x | 50x |
| max_margin_usage | 0.80 | 0.90 |
| max_position_notional | 100,000U | 200,000U |
| max_open_positions | 8 | 8 |
| max_risk_per_trade | 2% | 10%（置信度≥0.65、带止损止盈且 RR≥2） |
| daily_loss_stop | 15% | — |
| max_drawdown_from_peak | 30% | — |
| allow_bare_position | true | — |

### 9.2 AI 通道特殊档

- max_leverage：常规 20x / 强信心 25x。
- 默认逐仓（`margin_mode=ISOLATED`）。
- 强制 SL/TP（`allow_bare_position: false`）。
- 当日 -30% 熔断。
- 普通档单笔风险 ≤ AI 权益 × 2%；满足强信心全部条件时上限为 10%。

### 9.3 永不关闭的硬规则

- 所有减仓/平仓订单强制 `reduceOnly`。
- 同一决策周期内不得重复发相同方向订单（幂等 `clientOrderId`）。
- API Key 永不开启提现权限（币安 API 本身也要求 key 关闭提现）。
- 行情过期、账户状态无法核对时，不新开仓。
- 人工可在任何时刻切到 `pause` / `close_only` / `emergency`。

## 10. 复盘机制

### 10.1 自动复盘

- UTC 00:05 之后，慢循环检测到即自动生成昨日复盘报告。
- 最多回填最近 7 天的缺口。
- 重启不会重复跑（按 `daily_reviews` 表的 `review_date` 判重）。

### 10.2 复盘内容

- 交易归因：判断错误 / 执行问题 / 数据问题 / 风控拦截正确 / 市场随机。
- 每个 Agent 的贡献评分与错误清单。
- 主 Agent 引用策略库后的实际表现。
- AI 通道单独统计，与策略通道分离。
- 明日注意事项。

### 10.3 手动复盘

```powershell
.venv\Scripts\python.exe scripts\run_review.py
```

报告位置：`data/reviews/YYYY-MM-DD.md`。

## 11. 审计与日志

### 11.1 SQLite

`data/agent_trader.sqlite`：

| 表 | 作用 |
|---|---|
| `agents` / `agent_runs` | Agent 名称、版本、每次运行（起止时间、状态、模型、token、估算成本、延迟） |
| `artifacts` / `llm_calls` / `tool_calls` | 每个 Agent 输出的结构化 JSON + sha256；LLM 完整 prompt/response + 工具调用 |
| `trade_decisions` / `trade_intents` | 主 Agent 每轮决策；每个交易意图全字段 + 状态流转 |
| `risk_verdicts` | 风控放行/拒绝/降额及原因 |
| `orders` / `positions` / `portfolio_snapshots` | clientOrderId、交易所单号、成交、状态；当前与历史仓位；权益快照 |
| `signal_events` / `signal_tickets` | 信号触发、ticket 状态 |
| `decision_conflicts` | 通道冲突（如 AI 单与策略单同 symbol） |
| `channel_daily_stats` / `daily_rebalances` | 双通道每日统计、6:4 重算 |
| `risk_events` / `daily_reviews` / `agent_scorecard` | 熔断/断线/异常、人工干预；每日复盘；Agent 滚动评分 |

### 11.2 JSONL 原始日志

- `data/logs/YYYY-MM-DD/{agent}.jsonl`：每个 Agent 的输入/输出/错误。
- `data/logs/YYYY-MM-DD/llm_raw.jsonl`：完整 prompt/completion。

### 11.3 每笔交易必答 5 问

1. 当时哪些 Agent 提供了什么信息？
2. 主 Agent 引用了哪张策略卡？为什么？
3. 风控是放行、降额还是拒绝？
4. 订单从发出到成交用了多久？实际价差多少？
5. 最终盈亏应归因到哪里？

## 12. 常见操作

### 12.1 切换执行模式

1. 改 `.env` 的 `EXECUTION_MODE`（或在控制台 `/api/mode`）。
2. 重启 `scripts/run_web.py` 或 `scripts/run_phase1.py`。
3. 缺 key 时自动回退 `paper`，并在 `risk_events` 记 `broker_fallback_paper` 警告。

### 12.2 重置资金（仅测试模式）

- 控制台：`POST /api/capital/reset`（实盘模式被拒）。
- CLI：无直接命令；删除 `data/capital_state.json` 并重启，或在 `service.py` 调 `capital.manual_reset()`。

重置后 `session_equity` 回到 500U；具体基线口径以 `config/settings.yaml` 和资金状态文件为准。

### 12.3 紧急平仓

控制台右上角 → `emergency` 按钮，或 `POST /api/control` `{"state": "emergency"}`：

- `broker.close_all()` 一次性平掉所有通道、所有 symbol。
- 记 `manual_emergency_close` (critical) 事件。
- 实盘模式同样适用（如果你真的在 live 跑）。

### 12.4 切换到强信心档

- 编辑 `config/risk_learning.yaml` 的 `strong_*` 字段。
- 触发条件：模型在 `submit_decision` 中给 `confidence >= 0.65`，提交有效 SL/TP，且实际
  `RR >= 2`。
- AI 通道强信心档上限是 25x（不是 `strong_max_leverage: 50`），由 `ai_strong_max_leverage: 25` 限定。

### 12.5 调慢循环节奏

`config/settings.yaml`：

```yaml
decision_cycle:
  interval_minutes: 10       # 慢循环
  fast_interval_seconds: 30  # 快循环
  query_budget: 4            # 主 Agent 每轮工具调用预算
```

`scripts/run_phase1.py --loop --interval-minutes 5` 临时覆盖。

### 12.6 调整双通道权重

`config/settings.yaml`：

```yaml
channels:
  strategy_weight: 0.6
  ai_weight: 0.4
```

次日 UTC 00:00 自动重平衡；如需立即生效，手动调 `ChannelManager._rebalance_if_needed()` 或重置通道状态。

## 13. 故障排查

### 13.1 "phase1 start" 后立即退出 / 没有 run 输出

- 默认路径检查 `SENSENOVA_API_KEY`；显式 WorkBuddy 路径检查
  `MTA_AI_DECISION_PROVIDER=workbuddy`。联网验收使用 `scripts/verify_llm_provider.py`，脚本不会输出密钥。
- 看 `data/agent_trader.sqlite → risk_events` 最近 `cycle_error` 事件。

### 13.2 控制台 500 / 502

- 慢循环或快循环异常未兜住。检查 `risk_events` 表 `cycle_error` / `fast_cycle_error`。
- 重启 `scripts/run_web.py`。

### 13.3 余额显示 5000U（demo 模式）

- 旧版 bug：手动重置时 `baseline` 被强制设 0；已修（F1，2026-09-01）。
- 升级到最新代码 + 删除 `data/capital_state.json` 即可。

### 13.4 通道资金不随会话权益变化

- 旧版 bug：`_channel_day_start()` 优先返回陈旧存储值；已修（F2）。
- 升级代码即可。

### 13.5 重置后页面仍显示旧值

- 旧版 bug：`_latest` 缓存未刷新；已修（F4），重置后控制台立即刷新。
- 升级代码即可。

### 13.6 保护单没挂上

- 实盘执行层若挂不上止盈/止损必须重试；仍失败则立即平掉该仓位（`M1` 待办：纸面加仓路径只能收紧不能放宽）。
- 看 `risk_events` 表 `futures_min_qty_skip` / `futures_leverage_error` / `futures_fill_unconfirmed`。

### 13.7 Token 暴涨、模型反复重试

- 多半是 schema 与运行时闸门漂移；2026-09-01 已统一到 `ActionSpace`（一处定义，三处复用）。
- 如果还出现：看 `data/logs/YYYY-MM-DD/llm_raw.jsonl`，找 `submit_decision` 校验失败的 tool result。

### 13.8 没有任何 ticket

- `SignalScanner` 静默：`strategy_cards.json` 缺 `indicatorized: true` 卡片、策略卡引用未注册函数，或行情扫描失败。生产运行时不再依赖 `strategy_lab_src` 路径。
- 生产默认关闭 universal 扫描：`signal_scanner.universal_cards: false`，仅扫卡片已回测的 symbol；开启前必须先完成目标币种的样本外验证。
- 在“双通道”页面查看“信号扫描状态”：`行情组合` 分子等于分母且异常数为 0，说明扫描正常；本轮 ticket 为 0 只代表最新已完成 K 线没有满足条件。
- 扫描器只读取已收盘 K 线并按 `策略卡 + symbol + timeframe + bar_open_time` 去重，同一根 K 线不会每 10 分钟重复发票据。
- DNS/TLS/限流冷却属于整轮行情故障。系统首次识别后会短路本轮剩余 K 线请求，并合并为一条 `signal_scan_error`，避免慢循环被逐项重试拖住。
- `data/signal_scanner_state.json.last_scan` 保存最近一轮模式、品种、成功/失败行情组合数、ticket 数及自动过期数，可用于离线排查。

## 14. 限制与已知问题

### 14.1 历史 M1–M7 复核

| 编号 | 当前状态 | 证据或剩余风险 |
|---|---|---|
| M1 | 待处理 | PaperBroker 同方向加仓仍会覆盖原有 SL/TP，尚未实现保护性合并或拒绝。 |
| M2 | 待处理 | PaperBroker 已实现盈亏仍缺少手续费模型，和实盘净收益口径不完全一致。 |
| M3 | 已完成 | OpenAI 兼容客户端已有有界重试、Retry-After 协调和绝对截止时间回归。 |
| M4 | 已完成 | ActionSpace、校验器与运行时风控共用谓词，图执行传递 `execution_prices`。 |
| M5 | 待处理 | `_position_margin` 成交后仍可能读取缓存持仓，存在记录零值或旧保证金的风险。 |
| M6 | 待处理 | Binance 的 `margin_used`、`available_cash`、`equity` 仍会把部分异常折叠为 0。 |
| M7 | 已完成 | Paper 与 Binance `close_all` 均从账本/台账保留来源归因，并接入生命周期对账。 |

“已完成”仅表示已有代码和离线证据；待处理项需要单独实现和回归，本次复核不改变风险档。

### 14.2 实盘已经接入，但发布门禁未完成

- live profile 已隔离运行并具备订单、账户、保护和 Outbox 对账；小额运行不等于正式发布 GO。
- 最终候选仍需满足版本化观察、30 笔可归因闭合 Demo 交易和外部运维检查。

### 14.3 不适合

- 高频/做市（慢循环 10 分钟 + 快循环 30 秒）。
- 大资金或无人值守生产（当前仍缺最终样本门禁、正式托管和已验证外部告警）。
- 多用户（无认证，监听 `127.0.0.1`）。
