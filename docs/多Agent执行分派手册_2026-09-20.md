## 1. 执行主体映射

| 角色 | 执行单元 | 任务序列 | 说明 |
|---|---|---|---|
| I 集成负责人 | 主会话（协调者） | U00 → 集成 → U09 → U12 | 契约、共享文件、迁移编号、合并、门禁、状态台账 |
| A 账本 | 子代理线 A | U01 | 收入成本闭环 + DL05/DL06 + RV01–RV03 回归 |
| B 持仓与执行 | 子代理线 B | U04 → U02 | 部分成交/保护实现 → 管理授权与有界退出 |
| C 决策证据 | 子代理线 CD | U03 → U05 → U08 | 逐意图证据 → 决策 trace → 策略漏斗 |
| D 影子研究 | 子代理线 CD（与 C 串行） | U06a | 首批只做隔离与口径修正；U06b/U07 后置 |
| E 运维 | 子代理线 EF | U13 → U14 | RuntimePaths/托管恢复 → 外部告警与失联检测 |
| F 发布与可维护性 | 子代理线 EF | U15 → U10a | 运行身份/有效配置 → 发布包与运维说明 |
| Q 独立 QA | 独立子代理（每轮换） | 契约反例、最终验收、回归 | 不得与作者同会话；W0 登记 DC01–DC16 映射 |

会话规则：

1. 一个任务 = 一个新作者子代理会话（fresh context）；修复 = 该任务新会话，携带上一轮提交包与审查记录。
2. 审查 = 每个审查角色一个新会话；Q 验收 = 每轮一个新会话。作者不得担任自己任务的审查者。
3. 子代理没有跨会话记忆：作者与审查者返回提交包和审查记录，由I单写JSON；任何子代理不得直接改主台账。
4. 同模型独立会话可以担任审查者，但审查记录必须注明“同模型偏差限制”。

并发与降级：

- 首批最多 4 条实现线；线内任务串行，线间并行。Q 线不计入实现线。
- 可用并发不足时按规格 §2 降级：2 线 = A/B/C 合并、D/E/F 合并；Q 轮换不变。
- 新增会话优先写反例与审查，不增加共享文件竞争。

## 2. 工作区、分支与数据隔离

项目根可能仍是运行目录，禁止将其默认作为开发集成区。W0先只读盘点Demo/live进程、代码根、数据根、实例锁和启动路径；不读取凭据内容，不自动停服务。默认由I在独立 `mat-wt/I`、`integration/unattended-v3` 分支集成；子代理只能写获分配的隔离工作区。未证明运行隔离前，不在项目根checkout、合并、改配置或执行代码。

工作区根：`<工作区根>`（以下均是计划路径，本手册不创建目录）。

| 线 | 目录 | 分支序列 | 内容 |
|---|---|---|---|
| I | `mat-wt/I` | `integration/unattended-v3` | 台账、契约、共享适配、集成候选 |
| A | `mat-wt/A` | `task/U01` | 账本与复盘修复 |
| B | `mat-wt/B` | `task/U04` → `task/U02` | 执行与管理 |
| CD | `mat-wt/CD` | `task/U03` → `task/U05` → `task/U06a` → `task/U08` | 证据/遥测/影子 |
| EF | `mat-wt/EF` | `task/U15` → `task/U13` → `task/U14` → `task/U10a` | 身份/运维/发布 |
| Q | `mat-wt/Q` | `qa/<ID>/<round>` | 精确候选+独立测试；同一工作区不并发换版 |
| 审查 | `mat-wt/reviews/<ID>/<role>/<session>` | detached候选 | 只读业务代码，报告返回I归档 |

创建命令示例（由I在批准W0后执行；路径和commit必须先验证，存在同名目录/分支时停止核对，禁止强制覆盖）：

```text
git -C <absolute-repo> worktree add <absolute-worktree-A> -b task/U01 <task-base-commit>
```

基线与W0自举顺序：

1. I核对运行隔离、现有dirty变更及文档清单。只纳入本分派包和其引用的规划文件，不用git add .混入无关文件；规划文档提交记为planning_commit。若项目根为运行目录，在隔离区应用经过核对的文档补丁并提交，不动运行checkout。
2. 创建I集成区及W0专用审查工作区，基于planning_commit，不要求尚未存在的契约标签。I实现K01–K06实际schema、正反golden与契约测试，Q/C/B在各自工作区审查；占位文件不能通过冻结。
3. U00完整候选验收后由I冻结contract-v3.0。若标签已有，验证目标，禁止移动已有标签。冻结commit与规划commit不同；用后续独立台账提交记录contract_commit及U00完成证据，避免要求一个commit记录自己的hash。
4. 各任务保留contract_commit作接口基线，task_base_commit取分派时已审核的集成HEAD。已集成依赖必须包含在该代码基线中，记录dependency_commits；尚未集成的依赖写pending_dependencies，基于冻结接口/夹具先行实现，不宣称联调完成。
5. 依赖就绪后I刷新集成候选，带入全部依赖、作者提交和共享适配；作者及Q复验。不得始终从旧contract标签新建后续任务，也不得复用旧候选测试冒充新代码通过。
6. 换线内任务前确认前任务提交包与dirty变更已安全归档，未完成文件锁已释放；禁止reset --hard清场。命令使用绝对路径和git -C。依赖安装由I从锁定制品准备隔离环境，测试强制禁网；不得复制含生产凭据的环境。
7. W0确认实际编排器、模型标识、上下文与并发额度；Task(general)仅为编排示意，必须映射为已验证的实际接口，不能假定该工具必然存在。失败时保持任务PLANNED，不擅自换模型或启动本地Agent。

数据隔离（硬规则）：

- 禁止把真实 `.env`、`data/`、密钥、账户标识或运行实例复制到任何 worktree。
- 测试使用临时项目根、显式测试环境、禁网与路径访问守卫，拒绝访问真实数据根；用临时哨兵/调用记录验证隔离。运行服务会正常改真实状态，不能以其全局hash不变作为测试断言；子代理也不得为取hash读取真实账本。
- 不得启动真实服务、不得下单/撤单、不得发送真实告警、不得修改风险参数与 live 开关。
- 破坏性故障注入（F05/F06/F12/F14）仅限临时数据、隔离 profile 或专用演练宿主。

清理规则：线 worktree 保留至该线全部任务 INTEGRATED；Q 的验收产物由 I 合入或归档后才可清理。

## 4. 派发流程（子代理编排）

1. **启动确认**：implementation_requires已FROZEN才可正式实现；depends_on是合并门槛，不是启动门槛。未冻结时仅允许独立fixture准备，正式任务保持PLANNED；U00按§2自举。
2. **准备工作区**：从task_base_commit建任务分支，登记contract_commit、已包含和待集成依赖、精确文件所有权；I置IN_PROGRESS并记录作者actual_assignee。
3. **启动作者**：统一模板+角色卡+任务卡+JSON+相应规格；只授权独占路径和交付物目录，实际编排接口在W0验证。
4. **作者交付**：允许在自己分支本地提交。共享适配以完整统一diff/接口建议作为交付物返回I（不直接改共享源文件），I归档到docs/dispatch/patches/<ID>/<session>/；没有可复核适配不能宣称链路已接通。作者不得合并/推送/打标签。
5. **初审**：每个reviewer_roles独立会话审作者提交和适配建议；这是初审，不替代集成后审核。报告返回I，归档名为docs/dispatch/reviews/<ID>/<candidate-short>/<role>_<session>_r<n>.md；未有候选时目录使用author-<head-short>。
6. **构建候选**：全部depends_on已INTEGRATED后，I在隔离集成区应用依赖、作者代码、共享适配及迁移，建立不可变integration_candidate_commit和tree hash；记录作者/适配commit清单。不得因此提前标INTEGRATED。
7. **独立验收**：作者复核适配，指定审查者复审最终候选；Q在该精确候选基础上添加独立测试commit，仅改获授权测试路径，记录candidate/test commit、命令、退出码、输出hash。审查和验收全部通过才REVIEWED。
8. **合入与失效**：I仅fast-forward晋级已验候选及已验QA测试提交并做集成检查，随后标INTEGRATED；代码、适配、契约、配置、依赖或测试改变需重新构建候选并重跑受影响审查/Q验收。冲突解决或cherry-pick形成新树不能沿用旧通过标记。
9. **修复与部署**：失败置CHANGES_REQUESTED或BLOCKED，作者新会话修复后回到候选验收。部署/观察证据满足后才VERIFIED；U12完整通过仍不自动启用live。

统一子代理提示词模板（规格 §7 模板 + 编排字段）：

```text
你是 <角色> 角色下的任务 <ID> 作者，执行线 <line>，worktree=<绝对路径>，分支=task/<ID>。
代码基线=<task_base_commit>；接口基线=<contract_commit>；契约版本=<contract-v3.0>；
已集成依赖=<dependency_commits>；待集成依赖=<pending_dependencies>。
先读：v3执行规格 §<章节>、任务清单 JSON 条目 <ID>、docs/dispatch/角色卡.md 中 <角色>、
docs/dispatch/任务卡.md 中 <ID>、以及任务涉及的现有实现。
遵守：USD-M 范围、风险档不变、live 保持关闭；只写 owned_paths；共享文件只向 I 提交适配补丁建议；
不读写真实 data/.env、不启动真实服务、不联网下单、不发真实告警；
允许在本人任务分支本地提交，禁止推送/合并/打标签；台账只由I更新。
交付：commit、接口说明、数据库变更建议、反例测试、实际测试输出（命令/exit/output_hash）、
风险与回滚说明、known_limits、live_side_effects=none。
验收：任务 offline_acceptance 逐条给证据；阻塞立即记录原因与下一责任人；不以 mock 通过替代在线验收。
完成后交给 <reviewer_roles> 审核；不要自己合并、发布、打 GO 或启动实盘。
返回：提交包（task_id/base/head/contract_version/changed_files/behavior_delta/migration/
tests/reviewer/known_limits/rollback/live_side_effects）；共享适配另附完整diff。
作者阶段candidate与qa字段可空；REVIEWED必须绑定最终candidate与qa_test_commit。
```

失败与超时处理：子代理超时或不可用时，I 保存当前 commit/patch、测试与未决问题，把完整交接包转派另一子代理；不无证据标完成；未提交的半成品不写入运行目录。

## 5. 审查与集成协议

状态机：PLANNED → IN_PROGRESS → READY_FOR_REVIEW → CHANGES_REQUESTED / REVIEWED → INTEGRATED → VERIFIED；任意环节可 BLOCKED，必须有阻塞原因和下一责任人。未分派任务保持 PLANNED。

提交包必需字段（JSON `verification_policy.required_artifacts`）：task_id、base_commit、head_commit、contract_version、changed_files、behavior_delta、migration、offline_test_evidence、deployment_test_evidence、reviewer、known_limits、rollback，以及contract_commit、dependency_commits、integration_candidate_commit、candidate_tree_hash、qa_test_commit、live_side_effects。作者阶段候选/QA字段可为null、部署证据为PENDING；REVIEWED前候选与QA证据须齐全，VERIFIED再核验部署。`live_side_effects=none`；测试输出只收脱敏摘要；真实账本导出的 fixture 必须剔除账户标识、凭据、签名与不必要个人信息。

审查记录要求：独立读取需求、自行设计反例、保留审查记录、注明同模型相关性限制；测试作者不能覆盖对方预期让测试通过。

集成采用依赖就绪队列，而不是强制串行等待某条业务线。一个合法的首批示例顺序（JSON dispatch.first_release_example_order同步维护）：

`U00 → U01 → U04 → U03 → U15 → U02 → U05 → U06a → U08 → U13 → U14 → U10a → U09 → U12`

U15必须先于U02/U13；U06a是首批必交，先于U09/U12；U09显式依赖U08，使用已集成漏斗接口。可交换无依赖任务，但不可跳过依赖。I对独占业务模块不代写；共享适配必须含作者交付与作者复核，不让I凭描述补造未审核业务逻辑。

迁移编号由 I 分配；`migration.apply` 禁止内部 commit 破坏原子性；失败注入验证回滚；旧数据可读。每次合入后跑受影响域测试，新增测试登记进明确 runner。RC 阶段执行完整 `check_quality` 与 `run_offline_regression`。

集成窗口：每日两次由 I 维护。窗口报告五项：本轮完成且有证据的任务、未解决 P0、接口变更、下一批 commit、观察窗口是否受影响。遇到共享文件冲突：暂停冲突补丁、继续独立测试，不把整条线空等在同一个文件上。

回滚：代码回退须 schema 兼容；否则用新修复版本或隔离恢复，不直接覆盖在用数据库；运行目录冻结、部署新目录切换；没有证据不复用“上次成功”的 GO。

## 6. 状态台账与汇报

JSON 为唯一状态源。I 在每次派发/审查/合入后更新 `status`、`evidence`、`blockers`、`actual_assignee`。

- actual_assignee只记录当前作者会话；修复转派历史进evidence。review_assignments分别记录角色、会话、候选、报告路径；qa_runs独立记录验收会话、candidate/test commit及结果，不覆盖作者。
- 审查记录及适配补丁仅由I归档到自己的集成区；子代理返回内容/本地交付物，不写主台账或其他会话目录。每项报告使用任务/候选/角色/会话/轮次唯一命名。
- 证据最小集：commit hash、测试命令/exit/output_hash、fixture 与 seed、脱敏说明。
- 每次集成窗口报告先在会话中输出，再压缩写入 JSON `evidence`/`blockers`。

## 7. 门禁、禁止事项与外部待决项

对全部子代理的硬禁止：

1. 不得读/复制真实 `.env`、`data/`、密钥或账户标识；不得启动真实服务、下单、撤单、发真实告警。
