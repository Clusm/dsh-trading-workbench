## 2. 源码发现

| 路径/函数 | 行为 | 影响 |
|---|---|---|
| client.js · POLL_MS / MARKET_POLL_MS | 常规均 8000ms | 无故障时也不是秒级持仓行情 |
| client.js · resolvePositions | mark/upnl 来自 /state.positions | 独立 marketPoll 不刷新持仓行 |
| client.js · marketSymbol | 只取第一个仓位或最近轮次标的 | 多标的场景不能靠该行情更新所有行 |
| client.js · 行情 useEffect | 依赖 marketNonce、marketPoll.data、stateData | /state 更新会清旧定时器重计时；3 秒状态更新时可能长期延后 8 秒行情请求 |
| client.js · 隐藏页面处理 | 后续完整读码确认已有全局 visibilitychange 监听 | 复用已有恢复刷新；轻量通道独立监听并清理，避免重复依赖账户状态 |
| host/integration.js · loadPortfolio | 8000ms 缓存，请求完成才写入缓存时间 | 与页面轮询叠加时可能复用上一快照，不能当作固定 8 秒端到端更新 |
| host/integration.js · fetchPortfolio | 等待账户、持仓、曲线、订单、成交、复盘等 Promise.allSettled | 慢的非行情查询也会拖持仓刷新 |
| execution/broker.py · snapshot | 正常缓存 2 秒，失败保留旧快照并冷却 | 必须同时显示数据时间及 stale |
| market/service.py · prices | 1 秒缓存，但每标的还查询 premiumIndex 与 depth | 不是理想的高频纯价格通道 |

## 3. 最小修复方向（待实施）

### P0：防止把旧数据当实时

1. 持仓价格与盈亏直接显示最后成功时刻；失联时标注“历史快照”，保护状态也不能显示为已实时确认。
2. 页面级“服务在线”和“交易所数据可用”分别显示。上游恢复后以新证据解除过期状态，不在前端把 stale 清零。
3. 当前地域限制属于连接可用性问题，需按合法服务可用条件处理；不要改变代理/出口规避限制。

### P1：独立轻量价格更新

1. 保留账户/订单快照较慢刷新；为持仓标记价建立独立、单请求在途的轻量通道。首版可用 2 秒批量 REST，先测请求权重和延时；不直接把完整 /state 改为 1 秒。
2. 查询全部持仓标的，使用标记价而非最新成交价混替。现有 prices 同时取深度，需拆出轻量用途或减少无关请求，避免每 2 秒重拉订单簿。
3. 修复行情 timer 依赖；不要因账户快照更新反复清零计时器。页面隐藏降低/停止页面刷新，恢复可见立即刷新；后台仓位管理独立持续。
4. 价格有 source/as_of/received_at/stale；新账户/新环境清缓存，同标的拒绝乱序旧数据覆盖。
5. 官方账户盈亏继续用账户事实。若显示实时估算盈亏，必须单独命名，使用已确认仓位量和方向，不能写入账本或取代风控事实；首版也可以只加快标记价并保留盈亏时间标签。

### 后续选择

若批量 REST 在当前标的数量下达不到目标，再引入一个 Service 公共标记价 WebSocket 连接，Host/页面订阅同一缓存，断线降级低频 REST；不要每个页面/仓位各开连接。保护与执行不得依赖浏览器在线。

## 4. 验收建议

- 上游正常时，先测基线；目标为可见页面标记价数据年龄 p95 不超过约 3 秒（2 秒轮询方案的工程目标，不含上游故障）。
- 断线时显示旧数据年龄和故障原因，不清空成零；重连与页面恢复可见能重新拉取。
- 同时运行 AI 轮次，不能饿死行情刷新；覆盖多标的、乱序响应、环境切换。
- 检查上游请求数量、权重、错误率与并发，无轮询请求堆积。
