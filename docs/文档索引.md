# 文档索引

最后更新：2026-09-21（U10a：新增发布包章节，并为历史材料补"旧版"标记与免责声明）。

本页是项目文档入口。判断当前系统行为时，优先阅读"当前权威文档"；带日期的计划、事故
报告和设计稿用于解释历史决策，**不自动代表当前代码状态**。代码、锁定配置和运行 API 与
文档冲突时，应先停止扩散错误结论，再以测试和只读运行证据复核后更新文档。

## 版本标记约定

| 标记 | 含义 | 使用方式 |
|---|---|---|
| **现行** | 描述当前代码行为；与代码冲突时以代码为准并立即修正文档 | 可直接作为操作依据 |
| **旧版** | 某个时间点的复盘/核查/计划快照；**其结论、行号与"待办"均已过期** | 只能用于了解当时的判断依据，不得据此操作或作为验收证据 |
| **设计稿** | 方案意图；落地差异以运行手册为准 | 先读运行手册再看设计稿 |
| **流程记录** | 编排/评审/状态记录，属过程证据而非交付物 | 不进发布包，不作为能力声明 |

`旧版` 文档一律保留原样（事故与决策证据不能因"计划已完成"改写或删除），但**不再更新**；
若其中的结论今天仍然有效，须先迁入现行文档并附代码指认，再引用。

  [方案细审与修订记录](无人值守方案细审与修订记录_2026-09-19.md)。
- **不进发布包**（打包时显式排除，理由见 `scripts/create_release_package.py` 的
  `EXCLUDED_PATH_PREFIXES`）：评审证据 `docs/dispatch/reviews/**`、待应用补丁
  `docs/dispatch/patches/**`、`docs/dispatch/RESUME.md`、
  `docs/dispatch/w0_runtime_inventory.md`、`docs/dispatch/交接说明_*.md`。
  它们是流程记录（且刻意引用凭据模式），随部署工件分发会重演密钥扫描噪声，也会
  把"未合入的补丁"当成已交付内容。

以上编排材料中"已集成/已验收"的描述**只对内部分派有效**：代码 INTEGRATED 不等于任何
任务 VERIFIED，实盘仍处于未启用状态。

## 脚本入口索引

| 类别 | 入口 | 说明 | 包 |
|---|---|---|---|
| 启动 | `scripts/run_web.py` | 统一前台/SCM 生命周期入口；必须显式指定 live profile；`--verify-package` 只读自检 | runtime |
| 托管 | `scripts/windows_service_host.py` | SCM 宿主入口，`sc.exe` 只由管理员人工执行 | runtime |
| 托管校验 | `scripts/validate_windows_service_plan.py` | 只读校验 SCM 计划并打印待执行命令 | runtime |
| 临时分离启动 | `scripts/start_web_detached.py` | 当前过渡方式，不等同于无人值守托管 | source |
| 质量门禁 | `scripts/check_quality.py` | Ruff、编译、风险锁、依赖锁和密钥扫描 | source |
| 离线回归 | `scripts/run_offline_regression.py` | 默认禁网，不读取真实凭据或运行账本 | source |
| 发布包 | `scripts/create_release_package.py` | 打包 + 解压自检（`--self-check` / `--verify`） | runtime |
| 发布评估 | `scripts/report_release_readiness.py` | 7 天、200 候选、30 笔闭合交易等严格门槛 | runtime |
| Demo 验收 | `scripts/report_demo_acceptance.py` | Demo 候选、闭合归因交易和观察天数 | runtime |
| 实盘预检 | `scripts/preflight_live_account.py` | 只读核对账户模式、仓位、订单与保证金 | runtime |
| 健康守望 | `scripts/health_watch.py` | 不构造 TradingService 的只读监控 | runtime |
| 恢复 | `scripts/create_recovery_bundle.py` / `restore_recovery_bundle.py` | 停写一致性恢复包与只写新目录恢复 | runtime |
| 恢复核验 | `scripts/ops/verify_recovery_plan.py` | 恢复计划与门禁核验（U13） | runtime |
| LLM 验证 | `scripts/verify_llm_provider.py` | 显式在线协议检查；不会读取账户或下单 | source |

命名约定：`smoke_*` 是隔离冒烟；`probe_*` 和 `verify_*_live` 可能联网；`diag_*` 默认只读；
`cleanup_*`、`repair_*` 会改变状态，执行前必须先预览目标并准备后置核验。何种脚本进入
`runtime` 包由 `scripts/create_release_package.py` 的 `RUNTIME_SCRIPTS` 显式清单决定，
与运行手册 §3.1 的清单一致（由离线冒烟逐项比对）。
