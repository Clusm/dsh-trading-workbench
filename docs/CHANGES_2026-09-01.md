## 第二轮修复（H1–H4，已合入并验证）

### H1：`/fapi/v1/leverage` 设置失败导致整单中断 → 降档重试

- **位置**：`src/exchange/binance_futures.py` `_open()`
- **问题**：各币种最大杠杆不同（BTC 125x，山寨常为 20x/50x），AI 强信心档 25x 打到上限会抛 -4028，异常穿透导致整单丢失且模型不知情。
- **修复**：
  - 新增 `_symbol_max_leverage()`：从 `/fapi/v1/leverageBracket` 取该币种最高风险档的 `initialLeverage`。
  - `_open()` 中对 `/fapi/v1/leverage` 调用加 try：失败后降档到交易所上限重试；重试仍失败则放弃本单并记 `futures_leverage_error`（critical），降档成功记 `futures_leverage_downgraded`（warn）。

### H2：CLI 路径不传 `execution_feedback` → 双路径统一

- **位置**：`src/core/service.py`、`scripts/run_phase1.py`
- **问题**：Web 路径（service.py）把上轮执行反馈喂给主 Agent；CLI `--loop` 路径没有，AI 对上轮执行结果失明，重复犯错。
- **修复**：
  - `service.py`：`_build_feedback` 逻辑抽成模块级函数 `build_execution_feedback(state, decision, channel_status, broker_state)`，Web 路径委托给该函数，避免口径漂移。
  - `run_phase1.py`：`run_one_cycle()` 新增 `execution_feedback=None` 参数并透传 `build_graph`；循环体维护 `execution_feedback` 变量，每轮结束后用 `build_execution_feedback` 重建并传入下一轮。

### H3：裸 JSON 输出绕过业务校验与持仓必答 → 补校验并降级

- **位置**：`src/agents/orchestrator.py` 裸 JSON 回退分支
- **问题**：模型不走 `submit_decision` 直接输出 JSON 时只做宽松解析，`check_decision`（杠杆/止损校验）和 `check_position_reviews`（持仓必答）都被绕过。
- **修复**：宽松解析成功后，若 `action_space` 可用，依次执行 `check_decision` 与 `check_position_reviews`；发现任何 issues 则降级为 `no_trade`、把原因写进 reasoning 并记 `decision_downgraded`（warn），不再静默放行。

### H4：`_wait_fill` 超时返回非终态数据 → 未确认成交标记

- **位置**：`src/exchange/binance_futures.py`
- **问题**：12 次轮询后订单仍未到终态时返回最后一个非终态 dict（或空），调用方 `avgPrice or 0.0` 得 0，污染记账与 lessons 归因。
- **修复**：
  - 新增静态方法 `_fill_confirmed(data)`：仅 `FILLED`/`PARTIALLY_FILLED` 且 `avgPrice > 0` 视为确认。
  - 开仓、逐仓平仓、`close_all` 三条路径均累计 `fill_unconfirmed` 标志；任一 chunk 未确认时记 `futures_fill_unconfirmed`（warn）并在回执中带 `fill_unconfirmed` 字段，供对账与复盘识别。

**验证**：
- 全量 `py_compile` 通过（COMPILE_OK）。
- 功能验证脚本通过：`_fill_confirmed` 6 组用例、`build_execution_feedback` 结构、`run_one_cycle` 签名含 `execution_feedback`。

## 第三轮修复（UI 与资金口径，2026-09-01 下午）

### UI-1：控制台模式下拉只保留「模拟盘 + 实盘」

- **位置**：`src/dashboard/app.py`、`src/dashboard/templates/index.html`
- **问题**：下拉展示 paper/demo/testnet/live 四种，用户只需「模拟盘 + 实盘」。
- **修复**：新增 `VISIBLE_MODES = ("demo", "live")`，首页下拉与 `/api/mode` 只返回这两个；`SWITCHABLE_MODES` 保留完整四值供后端内部兼容。label 精简为「模拟盘/实盘」。paper/testnet 仍作为后端兜底保留。

### UI-2：去除「不设上限」字样 / 复盘默认展开

- **位置**：`src/dashboard/templates/index.html`、`reviews.html`
- **修复**：交易统计卡片去掉「不设上限」两处文字；复盘报告所有 `<details>` 默认 `open`（原仅首项展开）。

### F1：重置资金后仍显示 5000U（demo 基线错误）

- **位置**：`src/core/capital.py` `manual_reset()`
- **问题**：`new_baseline = 0.0` 无条件设 0，demo 模式下 `session_equity = 交易所余额(≈5000) - 0 = 5000U`。
- **修复**：paper 保持 `0`；demo/testnet 用 `交易所余额 - initial_equity`（与破产重置口径一致）。

### F2：通道资金/保证金上限不随会话权益动态变化

- **位置**：`src/core/channels.py`
- **问题**：`_channel_day_start()` 优先返回 `channel_state.json` 里陈旧的 `day_start_equity`（`initial_equity=200` 时代的残值 119.64/79.76），忽略每轮传入的最新 `session_equity`。
- **修复**：
  - `_channel_day_start()`：会话权益可用时实时计算 `session_equity × 权重`，不再信任同日陈旧存储值。
  - `_sync_locked()`：`day_start` 改用 `_channel_day_start()` 并同步写回 state。
  - 效果：通道资金/保证金上限实时按 6:4 联动会话权益。

### F3：重置资金后仍叠加历史平仓盈亏

- **位置**：`src/core/channels.py`
- **问题**：重置只平仓+调基线，但通道盈亏按 UTC 日从 `orders` 表统计，重置前的平仓亏损（-0.0973）在重置后仍被计入，导致策略通道显示 299.90 而非 300。
- **修复**：新增 `pnl_reset_at` 时间戳；`reset_day_start()` 写入重置时刻，`daily_trade_stats()` 只统计该时刻之后的订单。重置后通道盈亏从零重新累计。

### F4：重置后页面仍显示旧值（缓存延迟）

- **位置**：`src/core/service.py`、`src/dashboard/app.py`
- **问题**：`/api/channels` 优先返回 `_latest` 缓存的 channel_state，重置后页面继续显示旧值，要等下一个慢循环（10 分钟）才刷新。
- **修复**：新增 `service.refresh_after_reset()`，重置端点调用它——重置后立即实时 sync 并刷新 `_latest` 缓存，页面即时显示重置后的干净值。

**验证**：
- 全量 `py_compile` 通过（COMPILE_OK）。
- 重置后 `session_equity=500`、`strategy=300.00`、`ai=200.00`、`realized_pnl=0`、`closed_trades=0`。
- 下拉选项 = `demo / live`；页面「不设上限」出现 0 次；复盘 77 个 section 全部展开。
