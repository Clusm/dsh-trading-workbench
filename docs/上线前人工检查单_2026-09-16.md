## 1. 🌐 外部条件类

### 1.1 轮换对话中暴露的实盘 Key 并收紧权限（C-01）
- **为什么必须人工**：项目 R12 规定"对话中出现过的凭据视为已暴露需撤销换新"；收紧权限
  （禁提币/禁划转/仅 USD-M/绑定固定出口 IP）只能在币安后台操作，代码无法完成。
- **执行命令/入口**：登录币安 API 管理页撤销旧 `BINANCE_LIVE_*` Key，重新签发一对，
  新 Key 只写入 `.env.local`（已被 gitignore，勿写 `.env`）。
- **通过判据**：新 Key 仅 USD-M 合约权限、提币=禁用、划转=禁用、绑定固定出口 IP；
  只读预检（见 1.3）`can_trade=true` 且权限与预期一致。
- **失败时怎么办**：若无法收紧权限（如仍允许提币），**禁止上线**；旧 Key 立即撤销。

### 1.2 代理出口 IP 与账户白名单一致性（接管诊断 §7）
- **为什么必须人工**：出口 IP 由代理软件决定、账户白名单由币安后台决定，二者是否一致
  是外部事实，须人核对；不一致会导致 live 请求被风控/拒。
- **执行命令/入口**：在代理可用前提下运行只读预检（见 1.3）观察出口；
  并查代理进程实际出口 IP，与币安账户绑定的 IP 白名单比对。
  接管 manifest 记录的 `egress_id=162.248.75.128` 仍在白名单内方可用。
- **通过判据**：代理出口 IP ∈ 账户 IP 白名单；预检 `ok=true`。
- **启动要求**：live 启动命令同时传 `--egress-id 162.248.75.128`，使发布清单与
  网络观察窗绑定到已核验出口；不得以 `egress_id=unknown` 开启新仓。
- **窗口口径**：出口标识参与 `release_id` 计算；更换出口会自动建立新发布批次，
  7 天观察窗与 418/429 证据不得跨出口拼接。
- **失败时怎么办**：出口不在白名单 → 改代理出口或账户白名单，否则 live 不可启。

### 1.3 实盘只读预检（兼作 1.1/1.2 的通过判据验证）
- **为什么必须人工**：需真实网络与真实凭据，且必须在**代理可用**下运行（`.env` 的
  `MTA_NO_PROXY=1` 会强制直连导致 ConnectTimeout）；脚本强制只发 GET，不写盘不下单。
- **执行命令/入口**（项目根目录）：
  ```powershell
  $env:MTA_NO_PROXY="0"
  .venv\Scripts\python.exe scripts\preflight_live_account.py
  ```
  > 注意：必须 `MTA_NO_PROXY=0`，否则走 `.env` 的直连设定双双超时。
- **通过判据**：输出 JSON `ok=true`、`environment=live`、`can_trade=true`、
  `takeover.ok=true`、`positions=[]`、`orders=[]`、`algo_orders=[]`、
  `takeover.margin_cap.breached=false`。
- **失败时怎么办**：
  - `ConnectTimeout` → 出口不通，检查代理是否存活、`MTA_NO_PROXY` 是否确为 0；
  - `takeover.ok=false` / `margin_cap.breached=true` → 先处理存量仓位与保证金超限，
    勿强行接管；
  - 凭据缺失 → 先完成 1.1。

### 1.4 live 域名与账户权限只读核对（C-03）
- **为什么必须人工**：持仓模式（单向/双向）与账户权限是部署时的一次性核验，不能默认。
- **执行命令/入口**：同上 `preflight_live_account.py` 输出的 `takeover.position_mode`
  与权限字段。
- **通过判据**：`position_mode` 符合部署预期（当前账户为 `hedge` 且受支持），
  权限与 1.1 一致。
- **失败时怎么办**：模式不符（如预期单向却为双向）→ 在币安后台调整或修订风险配置，
  不得带着错配开仓。

### 3.1 账户级风险守卫 `audit_only` → `enforce` 决策（R-01）
- **为什么必须人工**：是否启用日亏损/回撤守卫**会直接改变开仓行为**，项目要求显式决定，

- **执行命令/入口**：团队评审后决定是否将 `stability.risk_guard_mode` 由 `audit_only`

- **通过判据**：决策已显式记录；若保持 `audit_only`，需明知"守卫不阻止开仓"。

- **为什么必须人工**：恢复 = 允许按既有风险档开**新仓**，是真实资金授权；代码不得自行决定。
- **执行命令/入口**（先停 live 实例，再改文件，再重启）：
