# 控制台 UI 重构方案（整合版）

> 目标：解决总览页信息超载（单页 8 个板块），让「现状 / 决策 / 历史」三类信息各归其位。
> 核心判断：拆页方向正确，但真正的收益不在「多拆一页」，而在三处修正。

---

## 0. 三处关键修正（相对原始设想）

| # | 原始设想 | 修正后 | 理由 |
|---|---|---|---|
| 1 | 新页叫「交易」 | 保留「交易」名，**副标题标注「决策中心」** | 「交易」语义偏向下单/成交，而本页内容是「信号 → 判断」的决策过程。导航宽度有限，用副标题兜底比改名为「信号与决策」更省空间 |
| 2 | 当前仓位搬进交易页 | **仓位留在总览** | 仓位是「此刻」的状态，与权益/盈亏同频，属高频信息。搬走后总览只剩历史曲线，首屏失去风险感知 |
| 3 | 搬三个散落板块 | **合成一条「决策链」卡片** | 用户真正的诉求是「为什么开仓」，散卡片需要自己脑补因果；链式布局一眼看清输入→结论→执行 |

**额外约束**：不使用「总览内部视图 tab」方案——各页轮询频率不同（总览 15s+1s 双频、情报类 30s），揉进一页会互相打架，且刷新后丢失 tab 状态。

---

## 1. 最终信息架构（按时间维度三分）

| 路由 | 导航 | 回答的问题 | 内容 | 模板 | 数据源 | 轮询 |
|---|---|---|---|---|---|---|
| `/` | 总览 | 现在怎么样 | 指标卡、权益曲线、**当前仓位+多空敞口条**、运行控制 | `index.html` | `/api/status` + `/api/prices` | 15s + 1s 双频 |
| `/decisions` **（新）** | 交易 | 为什么这么做 | 决策链（情报→策略匹配→策略调度→AI决策→执行结果）、决策记录 | `decisions.html` **（新）** | `/api/status` | 30s |
| `/orders`（原 `/trades`） | 订单 | 做过什么 | 每日盈亏、订单（可筛选）、仓位流水、资金快照 | `orders.html`（原 `trades.html`） | SSR | 静态 |
| `/events` | 风险事件 | 出了什么事 | 级别筛选 + 搜索 + 分页 | `events.html` | SSR | 静态 |
| `/reviews` | 复盘 | 做得怎么样 | 按日 tab 切换 | `reviews.html` | SSR | 静态 |
| `/agents` | 智能体 | 系统健康 | 运行统计、token 分布、调用明细、原始 JSON | `agents.html` | SSR | 静态 |
| `/channels` | 双通道 | 资金怎么分 | 双通道权益/胜率/保证金占用 | `channels.html` | `/api/channels` | 30s |

导航顺序：**总览 → 交易 → 订单 → 风险事件 → 复盘 → 智能体 → 双通道**（按使用频率排，运维视角页面后移）

### 关键实现优势：零后端数据层改动

`/api/status`（`app.py:1044 _compute_status`）已返回交易页所需的**全部**字段：

```
market / macro / onchain   → 情报三源（含 summary + regime + bias）
strategy_refs              → 策略匹配 refs 清单
strategy_decision          → 策略调度者 reasoning
ai_decision                → AI 决策者 reasoning
decision / risk_verdict    → 最终决策与风控结论
intel_cache / cycle_age_seconds → 情报缓存与新鲜度
```

即：**新交易页 = 1 条路由 + 1 个模板，后端不动。**

## 2. 逐页规格

### 2.1 总览 `/`（改）

- **移出**：最新情报、策略匹配、策略调度者/AI 决策者推理文本 → 迁入交易页
- **保留**：指标卡区、权益曲线、当前仓位 + 敞口条、运行控制
- **指标卡分组**（视觉分区，解决 8 卡平铺无重心）：
  - 账户组：会话权益 / 总盈亏 / 持仓数 / 今日开仓
  - 通道组：策略通道 / AI 自决策
  - 决策组：最新决策
- **控制按钮按「频率 × 危险度」分层**：
  - 主按钮仅保留「立即运行一轮」（高频安全）
  - 「暂停开仓 / 只平仓 / 恢复正常」收进「运行状态」下拉
  - 「紧急平仓 / 重置资金」挪至行尾红色区，**物理隔离**，实盘模式下追加二次输入确认
- **新增快捷跳转**：仓位卡片加「查看全部 →」→ `/decisions#step-5`；风险事件卡片已有「查看全部 →」

### 2.2 交易 `/decisions`（新）

顶部决策链卡片，纵向 5 步（`decisions.html`）：

| 步 | 节点 | 展示内容 | 右侧标注 |
|---|---|---|---|
| 1 | 最新情报 | 市场 / 宏观 / 链上 三源摘要 | 相对时间戳（`relTime()`） |
| 2 | 策略匹配 | 适用策略清单 + 适用/不适用徽标 | 适用策略数 |
| 3 | 策略调度者 | 本轮调度理由 `reasoning` | 可展开 JSON |
| 4 | AI 决策者 | 综合拍板 + 理由 + 耗时 | 可展开 JSON（熔断时标红） |
| 5 | 执行结果 | 成交订单 / 持仓变化 | 点击跳转 `/orders` |

- 每一步点击可展开对应 Agent 原始输出，**复用智能体页已有 JSON 数据**（`latest.market/macro/onchain/strategy.model_dump_json()`），后端零改动
- 底部：决策记录表（从 `/trades` 移入，`trade_decisions` 表，`LIMIT 30`）

### 2.3 订单 `/orders`（由 `/trades` 改名）

保留原有全部内容（counts 指标、每日盈亏柱状图、订单、仓位流水、资金快照），新增筛选：

- 直接**照搬 `/events` 已实现的筛选模式**（级别下拉 + 搜索框 + 分页）
- 筛选维度换成：方向（LONG/SHORT/全部）、状态（FILLED/PENDING/全部）、交易对搜索

### 2.4 通用改进

| 项 | 说明 | 优先级 |
|---|---|---|
| 导航扩至 7 项 | `base.html` nav 增加「交易」，`/trades` 改标「订单」 | P0 |
| 快捷键 `1-5` → `1-7` | `base.html` 键盘监听处硬编码，需同步扩展 | P1 |
| 导航红点角标 | 风险事件未读数、AI 通道熔断时显示红点，数据已在 `/api/status` | P1 |
| 空状态引导 | 「暂无仓位 → [立即运行一轮] 产生首轮决策」，替代纯提示文本 | P2 |
| 策略适用度 | 在适用/不适用徽标基础上补百分比条 | P2 |

## 5. 风险与回退

- **主要风险在前端模板，不涉及交易逻辑**，不会触发真实下单，实盘环境下也安全
- `/trades` 保留 302 重定向，外部书签与文档链接不失效
- 新增页面脚本必须写在 `{% block scripts %}` 内（`base.html` 公共脚本之后），否则 `apiFetch` / `smartInterval` 未定义会导致轮询静默中断；改动后用 `scripts/_js_check.py` 验证
- 建议改动前先跑一次 `python scripts/_js_check.py` 取基线
