## 执行与恢复检查

- 停用或切模式使旧开仓授权失效，已有仓位的保护和退出不因策略停用而取消。
- 超时退出取开仓确认版本，且显式未设置时长不会继承全局时长。
- 下单前持久化策略信号与退出期限；重启后，只为有已成交开仓订单证据且归属工作台的仓位恢复原始期限，不重新计时。
- 未知订单继续走现有 Outbox 原标识查询，不自动重发。外部仓位或缺乏归属证据的仓位不自动认领；此类异常仍须核对原订单与保护状态，不能算成真实恢复验收通过。
- 所有新增 Host HTTP 路由继续经过 DSH 请求准入；Service API 经过原鉴权。

## 部署及剩余验收

1. 使用打包产物升级 Host 与 Service 两端，先核对当前加载路径和运行身份；禁止直接覆盖原目录未提交修改。默认保持原生模式，新挂载策略保持未启用。
2. Service 启动后确认策略能力标识、数据库备份和旧账本数据；Host 加载后确认新标记价路由与策略界面。版本一致才开始执行验收。
3. 在服务可用的 Demo 环境中验证实时行情、页面隐藏恢复和多标的；再用明确授权的小范围策略验证入场—保护—退出、未知订单回查和重启恢复。
4. 满足上述条件后进行至少 24 小时稳定观察。代码测试通过不能替代实际连接、成交事实或稳定性结论。

当前交付为未部署的开发版本，不宣称工作台已经真实稳定运行。
