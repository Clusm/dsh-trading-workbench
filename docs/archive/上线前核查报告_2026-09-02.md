## 一、P0 — 上实盘前必须修复（✅ 已全部修复）

### P0-1 来源台账 ledger 并发丢更新 ✅
- **原问题**：`_load_ledger/_save_ledger` 无锁，dashboard 线程（紧急平仓/资金重置）与交易循环并发"读→改→写"互相覆盖；`.tmp` 路径共享可写坏文件。
- **修复**（`binance_futures.py`）：
  - broker 级 `threading.RLock()`（`_ledger_lock`），`_load_ledger/_save_ledger` 全程持锁；RLock 允许 `_record/_remove` 等辅助方法锁内重入。
  - **锁内零网络请求**：`_record_ledger_position` 重构为纯本地写，qty/entry 由调用方传入（原先锁内调 `positions(force=True)` 是嵌套网络请求，既放大延迟又制造锁序死锁风险）。
  - `_sync_pending_limits` 改"锁内快照 → 无锁对账（网络）→ 锁内合并保存"三段式，网络 IO 不持锁。
  - tmp 文件名带 `pid-线程id`，跨进程并发也不会互踩。
- **验证**：并发 4 线程交错读写，4 symbol 全在台账、新挂单不丢（`test_precheck_fixes` P0-1 三断言）。

### P0-2 被收养（adopt）的无主仓位永远不挂止损 ✅
- **原问题**：`_resync_protection` 在 `sl=None, tp=None` 时直接返回 True；adopt 的仓位裸仓运行。
- **修复**（`binance_futures.py`）：
  - `_record_ledger_position` 新增兜底保护：记录时无 SL/TP 立即按标记价 **-2% SL / +4% TP**（SHORT 方向相反）补挂，并发 `futures_protection_fallback` critical 告警。
  - `sync_positions` adopt legacy 时传真实 qty/entry（原先记 0）。
- **验证**：LONG/SHORT 各断言 SL/TP 方向与价格、critical 事件落库（6 断言）。

### P0-3 Dashboard 写操作接口零鉴权，本地 CSRF ✅
- **原问题**：`/api/control` 等写接口无 token，恶意网页可用 `fetch(mode:'no-cors', text/plain)` 触发紧急平仓。
- **修复**（`app.py` + 模板）：
  - 中间件 `_csrf_guard`：所有 POST `/api/*` 必须 ① 头 `X-Console-Token` 等于启动时 `secrets.token_urlsafe(24)` 生成的随机 token（打印到控制台 + 注入所有页面模板）② `Content-Type: application/json`。no-cors 模式浏览器发不出自定义头和 JSON Content-Type，两层都拦住。
  - `/api/control` emergency 增加请求体 `confirm:"emergency"` 二次确认。
  - 前端 `apiFetch` 对非 GET 自动携带 token 头；`setControl('emergency')` 自动附 confirm。
  - 实盘模式切换在原有弹窗基础上加 `requireText:'实盘'` 手输确认。
- **验证**：HTTP 实测 403（无 token）/415（text/plain）/400（无 confirm）/200（全参数）四态 + smoke_ui 断言。
- **保留确认**：host 默认 127.0.0.1；`.env` 未入 git。
