# 策略挂载 · 最小实现提案

后续执行以[持仓行情更新与策略挂载开发计划](quotes-and-strategies-development-plan-2026-11-16.md)为准；该计划明确首版默认范围、任务依赖和验收。

日期：2026-11-16。状态：待用户回答管理权限等问题；本文件为设计，不是已实现能力。

## 1. 产品定义

挂载是把用户策略转成系统可理解、可验证、可追踪的策略版本。挂载成功不等于开始交易，不等于策略有效或保证盈利。

第一版建议只收自然语言/Markdown/文本，不执行用户上传的任意 Python。策略代码上传需要独立沙箱与接口约束，暂不扩展。

## 2. 用户流程

1. 添加策略：粘贴内容/上传文本，可先命名，未命名给临时名称。
2. AI 理解：输出简洁的“我理解的交易规则”，指出缺失和矛盾；每个字段区分用户原文、推导、AI 建议。
3. 反馈提问：只问影响实际交易的缺项。将交易标的、周期、入场、退出、止损、持仓约束和无法获取的数据列为关键项；同一轮集中提最关键的 3–5 个问题，记住已答内容。
4. 完善确认：展示一页规则摘要、使用的账户默认限额、样例判断、仍不能执行的条件。AI 的补全建议由用户确认，不能偷偷猜出策略关键意图。
5. 挂载：后台校验通过后显示“已挂载 · 未启用”；用户可改名，名称与固定 strategy_id 分开。
6. 执行授权：单独启用，显示允许动作和预算。运行轮次引用 strategy_id/version，用户能看到本轮为何选择或跳过该策略。

状态保持精简：草稿 / 待完善 / 已挂载 / 已启用 / 已停用。临时数据故障显示在运行状态里，不修改策略内容状态。编辑已挂载策略产生新草稿版本，确认后下一轮生效，不覆盖旧仓位来源。

## 3. AI 理解与确定性执行

两类策略要明确区分：
- 规则型：如已定义周期的均线交叉，能用支持的指标和条件算出信号；AI 编译到受限规则结构，代码判断信号。
- 判断型：如“趋势健康且回调充分”，需要 AI 给出判断；必须明确其使用证据、输出格式、有效期及确定性风控限制，不能伪装为完全规则化。

不要求第一版支持任意策略语言。只支持当前已有行情与指标能力；无法量化、未支持的数据源或矛盾规则应进入待完善，不用任意代码 eval 或模型口头保证绕过。

策略原文是资料，不能覆盖系统权限、凭证、风控或执行接口。LLM 输出通过 schema 和语义校验；挂载前至少覆盖规则正例、反例和边界例。这些检查证明实现按规则运行，不证明策略获利。

## 4. 多策略管理的最小约束

暂定推荐方式：AI 推荐，用户确认启用；若用户选择自动调度，则仅在已明确授权的策略集合中选择。

第一版沿用当前账户单持仓限制，每轮最多选择一个策略产生新开仓意图，不增加多策略并发持仓。多个策略同时满足时，根据已确认优先级、适用行情和可用数据选取；冲突/证据不足可不交易，不采用多个模型投票来扩大风险。

- AI 不能新增/修改策略、提高风险预算或自动启用草稿。
- 所有策略共用账户级风险预算，不能每个策略各自申请一份完整账户额度。
- 已有仓位由开仓时的 strategy_id/version 负责管理；后续策略选择不自动转移归属。AI 不得让策略 A 的退出规则随意平掉策略 B 的仓位。
- 关闭策略默认阻止新开仓；已有仓位继续按原批准的保护/退出规则管理。平仓是另一个明确动作。
- 同一策略信号使用稳定标识（策略版本、标的、周期结束时刻、方向/条件），防止每轮重复执行同一个信号。
- 未指定的能力：加仓、反手、组合对冲、跨策略仓位净额管理，第一版不做。

## 5. 数据与代码落点

复用现有 SQLite、Host 决策链与 Service 执行器，不新增策略执行服务。

- SQLite 增量增加策略和不可变版本记录：strategy_id、name、version、status、原文、规范化规则、待答问题/答案、用户确认、时间与内容摘要。生命周期/权限由后台维护。
- Host 增加一个 strategy 模块处理草稿、澄清、确认及选择；复用现有模型调用、超时、预算和校验工具。候选筛选先用确定性规则，避免每轮让模型重读全部长文。
- 现有 chain.js 接收冻结的 strategy_id/version 与规则摘要；风险和执行模块仍是最终授权者，不开新下单旁路。
- Service 核验策略身份、状态、版本和授权；仅在 Host 日志写策略名不足以约束执行。停止策略要能使旧的开仓意图失效；已有仓位的风险减少管理权限单独保留。
- 订单、成交、仓位与轮次保存策略归因。第一版可在现有元数据扩展，实际存储形式实施前核对，避免重构全表。
- API 只需围绕四种业务操作：保存草稿、提交澄清答案、确认挂载、启用/停用。LLM 超时保留草稿，可重试，不重复挂载。
- 前端在现有设置/自动化中增加策略列表与编辑详情；AI 决策页显示本轮所选策略及选择理由。不新增独立控制台。

## 6. 分两步交付

第一步：添加/理解/提问/确认/命名/挂载；用既有历史时点证据演示规则判断，但不自动交易。交付目标是用户策略不会被 AI 悄悄改义。

第二步：一个已授权策略接入现有 Demo 执行链，完整验证开仓、保护、退出、重启、重复信号、停用后在途意图。单策略闭环后才允许 AI 在多个已授权策略中选择；仍不放开并发持仓。

验收必须包括：缺项阻止挂载、矛盾规则明确提问、改名不改变身份、修改不污染旧仓位版本、重复信号不重复下单、停用旧意图失效、策略亏损不自动改策略、行情过期不交易。

## 7. 等待明确的产品选择

1. 第一版只接自然语言/文档，还是也要运行上传代码？
2. AI 推荐后人工启用，还是允许在已授权集合中自动选择？
3. 缺失信息由 AI 提建议并确认，还是授权它自行补全？

用户尚未回答前，按“文本策略 + 建议确认 + 不自动启用”进行方案讨论，不据此启动交易或执行任意代码。
