## 1. 定稿结论（一段话）

现有系统的服务端（确定性风控 R00–R25、P1/P2 两次复核、审批令牌、执行租约、策略原语求值、信号去重、熔断）质量高，**保留并作为唯一的执行权威**。问题集中在 Host 编排：一轮 8 个 LLM 角色里，只有分析和做空方开场两次真正影响结果；“等待触发的 setup”被当成“立即执行的市价单”；策略只在 10 分钟槽里求值，而且是水平触发。定稿方向是 **v3.1：研判（LLM，只产出 setup）与执行（代码触发引擎，Host 定时器 + 服务端权威复核）分离，用户策略和 AI setup 统一为“可执行规则”**。

落地前有两件事必须先做：**恢复交易所访问（HTTP 451）**，以及**处理桌面明文实盘密钥**。

## 3. 最终目标架构（v3.1 定稿）

```
研判循环（LLM，每 10 分钟 / 平仓后 / 异动）      purpose=research，不持有租约
  筛选（代码，20 币取前 3）→ analyst（LLM×1）→ critic（LLM×1，不同路由，只能否决或收紧）
  → setup_score + 确定性风控折扣（代码）→ POST /api/setups（服务端校验后挂起）

触发引擎（代码，Host 定时器）                    purpose=trigger，每次派发才拿租约
  mark：每 15s；kline：收盘后 +3s
  POST /api/rules/scan → triggered（服务端确定性排序，已过滤冷却 / 已消费 / 过期 / 失效）
  → 租约 → 单币 cycle（满足 R14 ≤400s）→ P1（rule_context，服务端用新鲜行情复核、算仓位）
  →（可选）trigger_confirm 单次 LLM 复核，只能否决，超时也算否决 → P2 → finalize

持仓循环（阶段 5）：有持仓时研判切到 manage 模式；触发引擎只记录，不派发
```

接口、表结构、状态机、错误码以 **18 号文档第 4–6 节**为准，并叠加本文第 2 节 R2–R5 的修订（18 号文档已同步改正）。

### 3.1 用户策略的执行模式（最终）
| 模式 | 定稿行为 |
| --- | --- |
| `rule_direct` | 触发引擎派发 → P1/P2，0 次 LLM 调用。延迟从“最长 10 分钟”降到“≤15s / 收盘后 3s” |
| `ai_assisted` | 触发引擎派发 → `trigger_confirm`（1 次，≤600 token，低推理档位）→ P1/P2。**不再进入 8 角色辩论**。否决记入 `strategy_decisions(outcome='ai_vetoed')`，自动参加事后回测 |
| 多个规则同时触发 | 服务端确定性排序：用户策略优先 → `priority` → 挂起时间；删除 `StrategyAssistant.choose()` |
| 触发语义 | 新挂载默认边沿触发；旧版本保持水平触发，界面上提示 |
| mounted 与 native | 不再互斥：开启策略时，AI 研判照常产出 setup |

### 3.2 入场接受条件（AI setup）
- **追价上限** `max_chase_bps`：默认 15bp，上限 50bp；
- **成交时盈亏比** `min_rr_at_fill`：默认 1.5，且不低于 R10 的 1.2；
- 挂起时如果触发条件已经满足，拒绝挂起（`E_SETUP_ALREADY_TRIGGERED`），不追已经发生的信号。

### 3.3 `setup_score` 与确定性风控折扣（R6）
```
setup_score = 0.35·RR + 0.25·证据 + 0.20·数据健康 + 0.20·趋势一致
  RR       = clamp((rr_at_arm − 1.2) / (3.0 − 1.2), 0, 1)     rr_at_arm 按挂起时标记价计算
  证据     = min(1, 有效 evidence_refs 数 / 4)                 引用必须能在证据快照里解析到
  数据健康 = GOOD 1 / DEGRADED 0.5 / 其他 0（数据健康为 0 时不得挂起）
  趋势一致 = setup 方向与 4h 收盘价相对 EMA50 的方向一致 1，持平 0.5，相反 0
挂起门槛：setup_score ≥ 0.50
priority  = setup_score × critic 系数（pass 1.0 / tighten 0.8）
risk_pct  = min(卡片 risk_pct, critic 收紧值, 硬上限) × (DEGRADED ? 0.6 : 1.0)
```
权重是初值，影子运行 2 周后按“得分分位 vs 实际 R 值”校准一次，之后冻结版本。

## 7. 风险登记

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 原语表达力有限，AI setup 挂起率低 | 交易机会少 | 有意的取舍；先补 `volume_ratio`，按 `E_SETUP_UNSUPPORTED_CONDITION` 计数决定是否做 `sequence` |
| 去掉固定红蓝后方向偏差变大 | 单边风险 | critic 用不同的模型路由；按方向统计胜率并告警；AI setup 整体熔断（R4） |
| DSH 关闭时不扫描 | 错过触发 | setup 有过期时间；R5① 防止迟到入场；心跳告警（R13） |
| 15m 收盘触发时的滑点 | 成交价变差 | `max_chase_bps` + P2 的 `max_slippage_bps` + 成交时盈亏比 |
| 451 再次出现 | 全部停摆 | 显式出口代理 + 451 归类告警 + 退避 |
| 单一持仓上限下多个规则同时触发 | 只执行一个 | 确定性排序；没被选中的继续排队，并记录原因 |
